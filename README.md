# 심연의 계단

10층 아래 심연의 군주를 쓰러뜨리는 **턴제 던전 크롤러**. 빌드 단계 없이 브라우저에서
바로 돈다 — `public/index.html` 을 더블클릭하면 실행된다.

- 운영: https://abyss-stairs.bhmoon.workers.dev
- 저장소: `comzoo123456789-ops/abyss-stairs` (**비공개**)

```
public/           ← 배포되는 것은 이 폴더뿐이다
  index.html      화면 뼈대 + 시작 화면(직업 선택 · 조작 안내) + 도움말
  css/style.css   화면
  js/sprites.js   도트 엔진 32×32 (원시 도형 → 윤곽선·명암 → 캔버스에 굽기) + 지형
  js/sprites-art.js 인물·몬스터·물건 도트   ← 그림은 여기만 고친다
  js/sound.js     효과음 — WebAudio 로 합성 (음원 파일 0개)
  js/data.js      직업·무기·옵션·스킬·특성·몬스터 표         ← 밸런스는 여기만 고친다
  js/items.js     장비 굴림(등급·옵션·이름) + 능력치 합산     ← 아이템 규칙은 여기만
  js/dungeon.js   던전 생성 + 시야(재귀 그림자 던지기) + 보물방 + 함정 층
  js/game.js      턴 진행 · 전투 · 아이템 · 직업 능력 · 식별   ← 규칙은 여기만 고친다
  js/render.js    카메라 · 안개 · 사이드바 · 능력 버튼
  js/main.js      입력 · 부팅 · 시작 화면
tools/check.mjs   실제 Chrome 으로 화면 점검 (콘솔 오류 · 레이아웃 · 조작 · 시작 화면)
tools/anim-check.mjs  부드러운 이동 점검 (칸 사이 보간 · 걸음 프레임 · 연타 · 유휴 정지)
tools/arena.mjs       규칙만 돌리는 검사들이 함께 쓰는 판 (두 벌로 두지 말 것)
tools/mob-check.mjs   몬스터 행동 (속도 · 원거리 · 도망의 끝 · 소환 상한)
tools/kite-check.mjs  붙었다 떨어지는 춤 (쿨다운이 공짜가 되지 않는가 · 도망 값)
tools/fx-check.mjs    타격감 (무기별 궤적 · 피해 숫자 · 섬광 · 상태이상 색 · 히트스톱)
tools/deco-check.mjs  구역 장식이 바닥에 묻히지 않는가 (밝기 차를 숫자로)
tools/verify.mjs  전체 회귀 검사 (로직 + 직업별 밸런스 + 화면)
wrangler.toml     Cloudflare 배포 (정적 자산 Worker · public/ 만 올린다)
```

**`tools/` 는 웹에 올리지 않는다.** `wrangler.toml` 의 `directory` 가 `./public` 이라
검사 도구·README·설정은 배포에 안 들어간다(운영에서 전부 404 로 확인). `directory` 를
`"."` 로 바꾸면 그 순간 검사 도구가 누구에게나 내려가고, 저장소를 비공개로 둔 의미가
반쯤 사라진다.

## 캐릭터는 칸보다 크게 그린다 (32×48)

32×32 에 사람을 넣으면 **2등신**이 된다 — 머리 하나 몸통 하나로 픽셀이 끝나서
다리도 자세도 안 들어간다. 참고 시트(카엘렌·리라·발레리우스)와의 격차는 그리는
방법이 아니라 **해상도**였다.

- 주인공 셋을 **32×48** 로 통일했다. 가로는 칸과 같아 좌우로 안 넘치고(옆 칸을
  안 가린다) 세로만 1.5칸이다. 3.4등신이라 투구·어깨·허리갑·다리가 아직 다 들어간다.
- ⚠ 처음에 40×64 로 그렸더니 **지도에 비해 너무 컸다**(사용자 지적). 칸이 32px 인데
  세로 64 면 두 칸을 통째로 덮어 캐릭터가 지형을 가린다.
- ⚠ **줄이는 것은 다시 그리는 것이다.** 40×64 를 축소하면 픽셀이 뭉갠다 — 도트는
  목표 해상도에서 새로 찍어야 한다.
- ⚠ **그리는 차례가 곧 위아래다.** 오르넬의 얼굴을 먼저 그리고 두건을 나중에
  그렸더니 얼굴이 통째로 덮여 파란 덩어리만 남았다. 차례는
  ① 두건 껍데기(뒤) → ② 얼굴·수염 → ③ 앞 차양(이마만) 이다.
- 셰라는 **몸을 좁게** 그린다. 전사와 같은 폭이면 둘이 구분이 안 된다.
- 오르넬은 **다리를 안 그린다.** 로브가 바닥을 덮으므로 걸음은 자락이 흔들려서
  표현한다 — 다리를 억지로 넣으면 로브가 아니라 치마가 된다.
- (옛 기록) 전사를 **40×64** 로 먼저 그렸다. 4.5등신이 되어 면갑 · 어깨보호구 · 흉갑 능선 ·
  가슴 문장 · 허리띠 · 허리갑(타셋) · 정강이받이 · 쇠구두가 들어간다.
- ⚠ 가로는 **40** 이다. 48 로 해 봤더니 어깨가 넓어 뚱뚱해 보였다(시제품에서 확인).
- ⚠ **발을 칸 바닥에 맞추고 위로 넘치게** 그린다(`placeAt`). 로그라이크에서 흔한
  방식이고 위치가 안 헷갈린다 — 이 약속이 깨지면 캐릭터가 공중에 뜬다.
- ⚠ 갑옷·무기는 아직 32×32 다. **각자 제 크기만큼** 맞춘다 — 한 값으로 몰아서
  밀면 큰 몸에 작은 무기가 어긋난다.

**엔진에서 고친 것** — 판이 정사각형(`this.n`)뿐이었다.

- `Board(w, h)` 로 직사각형을 받는다(옛 `Board(32)` 호출도 그대로 돈다).
- `art(..., { w, h })` 로 스프라이트가 제 크기를 갖고, `bake` 가 그 크기로 굽는다.
- ⚠ **`outline` 과 `rim` 이 `b.n` 을 높이로 쓰고 있었다.** 세로로 긴 판에서 그대로
  두면 **40행 아래가 통째로 빠져** 다리에만 윤곽선이 안 붙는다 — 원인이 화면에
  안 드러나는 종류다. `b.w` · `b.h` 로 갈랐다.
- ⚠ 작은 초상 자리(HUD · 사이드바 · 직업 카드)는 정사각형 캔버스다. 40×64 를 그대로
  그리면 **다리가 잘린다** — `drawPortrait` 이 비율을 지켜 줄이고 바닥에 맞춘다.
  직업 카드는 **정수배로만** 키운다(3.5배 같은 값은 픽셀을 뭉갠다).

**⚠ 구획을 통째로 갈 때는 지워질 것의 목록을 먼저 센다**

캐릭터를 다시 그리며 `art("warrior")` ~ `art("rat")` 구간을 통째로 갈았는데,
그 사이에 **구역 장식 11개**(`p_crate`·`p_torch` …)와 `S.data.player` 별칭이
있었다. 함께 지워졌고 화면은 이렇게만 죽었다:

```
TypeError: Failed to execute drawImage … The provided value is not of type …
  at Renderer.draw (render.js:907)
```

**무엇이 없어졌는지는 한 글자도 안 나온다.** `bake` 가 없는 이름에 null 을 주고
`drawImage` 가 그걸 받아 터지기 때문이다. 그래서 verify 에 **「스프라이트」** 검사를
넣었다 — 직업·몬스터·소모품·구역 장식·무기·굴린 장비·render.js 가 문자열로 부르는
이름을 전부 모아 실제로 있는지 대조한다(일부러 하나 지워 잡히는 것을 확인했다).

- ⚠ 그림은 **두 파일**에 있다. `sprites-art.js`(인물·몬스터·물건)와
  `sprites.js`(문·계단·함정). 한쪽만 읽으면 멀쩡한 이름을 "없다" 고 한다.
- ⚠ `bake("p_" + pname)` 같은 **이어 붙이는 자리**는 이름을 알 수 없다 — 앞 조각을
  이름으로 세면 늘 빨개진다. 구역 장식은 `ZONES` 를 돌며 따로 센다.

**그림에서 배운 것**

- ⚠ 팔을 흉갑과 **같은 밝기**로 두면 한 덩어리로 붙어 보인다. 한 단계 어둡게 두고
  사이에 그늘 한 줄을 넣어야 실루엣이 갈린다.
- ⚠ 어깨보호구가 크면 팔을 통째로 덮어 "팔이 없는" 그림이 된다.
- ⚠ 두 다리를 붙여 두면 한 덩어리로 읽힌다 — 가랑이에 그늘 한 줄.
- 걸음 프레임은 `["f", n]` 으로 **다리만** 가른다. 몸을 한 벌 더 적으면 몸을 고칠 때
  두 곳을 고쳐야 하고 반드시 어긋난다.

## 공격 모션 — 팔이 실제로 움직인다

전에는 **몸 전체가 앞으로 밀리고**(lunge 130ms) 무기 **궤적**만 그려졌다. 팔은 한 번도
안 움직였다(사용자 지적). 프레임을 둘 더 둔다.

```
0  서 있기        1·2  걸음(왼발·오른발)
3  치켜듦          4    내려침
```

찌르는 동안 앞 35% 는 3, 나머지는 4 다(`Renderer.poseOf`). 찌르기와 **같은 시계**를
쓰므로 밀림·궤적과 저절로 맞는다. 무기는 `WEAPON_POSE` 로 손을 따라 옮긴다 —
무기 그림을 프레임마다 새로 그리면 7종 × 2장이 는다.

- ⚠ 팔을 **두 벌 적지 않는다.** 평소 팔은 `["f",[0,1,2]]`, 공격 팔만 `["f",3]`·`["f",4]`.
  몸통은 필터 밖이라 한 번만 적는다 — 몸을 고칠 때 다섯 곳을 고치는 일이 없어야 한다.
  (그래서 프레임 필터가 **배열도 받게** 넓혔다.)
- ⚠ 치켜든 팔은 **어깨보호구보다 나중에** 그린다. 앞에 두면 보호구가 덮어 "팔이 안
  올라간" 그림이 된다.
- ⚠ 그림은 앞을 보고 서 있다. 방향은 밀림과 궤적이 말해 주므로 **오른팔만** 움직이면
  된다 — 방향마다 다른 그림을 그리면 4배가 된다.
- ⚠ **그 프레임이 있는 스프라이트에만** 준다(`S.hasFrame`). 몬스터 16종에는 아직
  공격 프레임이 없어 걸음 프레임으로 떨어진다.

### ⚠ 없는 프레임을 부르면 그 부위가 통째로 사라진다 (오류는 안 난다)

공격 프레임을 넣으며 **서 있는 다리를 `["f", 0]` 으로만 묶어 두었다.** 3·4 를 부르니
다리가 하나도 안 그려져 **몸통만 떠 있는 그림**이 나왔다. 오류도 경고도 없다.
지금은 `["f", [0, 3, 4]]` 로 서 있는 다리를 공격 프레임에서도 쓴다.

`node tools/frame-check.mjs` 가 프레임마다 몸이 온전한지 픽셀로 잰다.

- ⚠ **총 픽셀 수로는 못 잡는다.** 다리는 몸 전체의 10% 남짓이라 통째로 사라져도
  총량은 90% 로만 준다 — 실제로 첫 판 검사가 이걸 놓쳤다(876 → 786, 문턱 70%).
  **세로 구간(위·가운데·아래)마다 따로** 재야 잡힌다(254 → 131 로 드러난다).
- `node tools/attack-check.mjs` 는 한 걸음 더 간다: 적을 옆에 세우고 **실제로 때려서**
  프레임이 3 → 4 → 0 으로 도는지 본다. 그림이 있는 것과 렌더러가 그걸 고르는 것은
  다른 얘기라, 둘 다 재야 한다.

## 글씨 — 픽셀 서체로 한글을 읽히려 하지 않는다

사용자 신고: "글씨체... 너무 보기 힘들고 잘 안보여". `tools/font-check.mjs` 로 재 보니
화면 글자 **70개 중 29개가 12px 미만**이고 **39개가 11px 격자를 벗어나** 있었다.

Galmuri11 은 **11px 비트맵**이다. 11 의 배수(11·22)에서만 픽셀이 딱 떨어지고 그 밖에서는
뭉갠다. 그런데 반응형 UI 의 글자 크기는 40여 가지다 — 전부 11·22 로 줄이는 것은 불가능하다.
그래서 **읽는 글은 Pretendard**, 도트 서체는 **제목 한 곳(22px)** 에만 남겼다.

```
--sans   Pretendard          읽는 모든 글 (한글이 어느 크기에서나 읽힌다)
--mono   Consolas+Pretendard 숫자·정렬 칸 (라틴은 고정폭, 한글은 뒤로 떨어진다)
--pixel  Galmuri11           제목 한 곳. **11 의 배수에서만** 쓴다
--title  Press Start 2P      아주 짧은 라틴 (Q·W·E·R·Lv) — 외곽선이라 격자가 없다
--num    VT323               큰 숫자 — 외곽선이라 격자가 없다
```

- ⚠ **도트 느낌은 글꼴이 아니라 캔버스 도트·픽셀 프레임·팔레트가 낸다.** 그쪽은 그대로다.
- ⚠ **글꼴 목록에 이름만 적어 두면 조용히 시스템 글꼴로 떨어진다.** Pretendard 가
  목록에는 있었는데 링크가 없어 맑은 고딕으로 나오고 있었다 — 오류도 안 난다.
- ⚠ 12px 미만 62곳을 들어올렸다(8→10 · 10→12 · 11→12.5 · 11.5→13). 계단은 지키고
  바닥만 올린다 — 전부 같은 크기로 만들면 위계가 사라진다.
- ⚠ `--ink-dim` 이 #9d8f77 이라 대비 3.75:1 이었다(빈 스킬칸의 W·E·R). #b5a88e 로 올렸다.
  이 값 하나가 화면 전체의 "부연 글자" 를 정한다.
- ⚠ **막대 색을 글자에 그대로 쓰면 안 된다.** 층 숫자에 `--hp`(#c0392b)를 썼더니 3.11:1 이었다.
  막대는 넓은 면이라 어두워도 보이지만 글자는 획이 가늘다 — 글자용 색을 따로 둔다.
- ⚠ 브라우저 기본 `<small>` 은 0.8em 이다. 12.5px 문장 안에서 10.4px 이 된다 —
  **크기는 물려받고 색으로만** 힘을 뺀다(비율로 줄이면 부모에 따라 또 바닥을 뚫는다).

## 체력·경험 막대 — 한 줄로 쭉 이어진다

- ⚠ **칸 눈금을 긋지 말 것.** 장부처럼 보이라고 20px 마다 세로줄을 얹었더니 막대가
  칸으로 쪼개져 **"피가 닳는 느낌" 이 사라졌다**(사용자 지적). 눈금은 지웠다.
  장부 느낌은 테두리와 종이결이 이미 낸다.
- 숫자는 **퍼센트**(0~100)다. 채워진 끝에 밝은 선을 둬서 어디까지 남았는지가 잡힌다.
- ⚠ 퍼센트만 두면 "12 남았다" 를 알 수 없다 — 로그라이크에서 그건 중요한 정보라
  **버리지 않고 덧댄다**: 손을 얹거나(hover·focus) 휴대폰에서 누르면 `58 / 62` 가 뜨고,
  `title` 에도 들어 있다. 누르면 2.5초 뒤 저절로 닫힌다 — 닫는 법을 또 배우게 하지 않는다.

⚠ 검사에서 겪은 것 둘. **페이지로 보내는 코드는 템플릿 리터럴을 거친다** — 거기 적은
`d` 는 Node 가 먼저 읽어 `d` 가 되고 브라우저에는 망가진 정규식이 도착한다(두 겹으로 적는다).
그리고 **opacity 에 전환이 걸려 있으면 켜자마자 읽은 값은 옛 값이다** — 전환을 끄고 잰다.

## 명령

```bash
node tools/verify.mjs                  # 전체 검사 — 고치고 나면 이걸 돌린다
node tools/verify.mjs 300               # 판수를 늘려 밸런스를 더 정확히
node tools/check.mjs --shot a.png      # 화면만 점검 + 스크린샷
node tools/check.mjs --cls mage        # 특정 직업으로 점검
node tools/check.mjs --touch --w 390 --h 844   # 아이폰 크기 · 터치 패드까지
node tools/check.mjs --play            # 죽을 때까지 실제로 두드려 종료 화면 확인
node tools/check.mjs --url https://abyss-stairs.bhmoon.workers.dev/   # 배포본을 잰다
node tools/anim-check.mjs              # 부드러운 이동만 따로 (보간·걸음·연타·유휴·스냅)
node tools/mob-check.mjs               # 몬스터 행동만 따로 (속도·원거리·도망·소환)
node tools/kite-check.mjs              # 붙었다 떨어지는 춤만 따로 (기회 공격·도망 값)
node tools/fx-check.mjs                # 타격감만 따로 (캔버스 픽셀을 직접 읽는다)
node tools/deco-check.mjs              # 구역 장식 대비만 따로
node tools/fx-check.mjs --shots out    # 연출 장면을 png 로 뽑아 본다

npx wrangler deploy                    # 운영 배포
```

Chrome 경로는 `tools/check.mjs` 맨 위 `CHROME` 상수에 있다. 설치 패키지는 없다
(wrangler 는 `npx` 로 그때 받아 쓴다).

⚠ **배포는 파일이 올라간 것으로 끝나지 않는다.** `--url` 로 배포본을 다시 재서 화면이
정말 도는지 확인한다 — 업로드 성공과 게임이 돌아가는 것은 다른 얘기다.

⚠ **배포 직후 `curl` 로 `?v=` 를 확인하면 옛 값이 나올 수 있다.** CDN 이 index.html 을
잠깐 들고 있다. 실제로 올라간 것이 v16 인데 v15 로 보여서 "배포가 안 됐다" 로 오진했다.
캐시를 우회해서 본다:

```bash
curl -s "https://abyss-stairs.bhmoon.workers.dev/?cb=$RANDOM" | grep -o '?v=[0-9]*' | sort -u
```

## 다른 컴퓨터에서 이어서 작업하기

필요한 것은 셋이다. 시크릿은 없다.

1. **저장소 읽기 권한** — 비공개라 계정이 초대되어 있어야 한다
2. **Node 18+** — `npm i` 는 필요 없다. 의존이 0개다
3. **크롬** — 화면 검사만 쓴다. 경로는 알아서 찾는다

```bash
git clone https://github.com/comzoo123456789-ops/abyss-stairs.git
cd abyss-stairs
# 그대로 public/index.html 을 열면 플레이된다. 설치할 것이 없다.

node tools/verify.mjs        # 검사 전부 (로직 + 화면)
npx wrangler login           # 배포하려면 이 컴퓨터에서 한 번만
npx wrangler deploy
node tools/check.mjs --url https://abyss-stairs.bhmoon.workers.dev   # 배포본을 다시 잰다
```

- **비공개 저장소다.** clone 할 때 GitHub 로그인(또는 토큰)을 한 번 물어본다.
- **크롬 경로는 `tools/chrome.mjs` 한 곳에서 정한다.** 흔한 자리 열두 곳을
  뒤져 있는 것을 쓰므로 대개 그냥 된다(크롬이 없으면 엣지도 받는다).
  못 찾으면 무엇을 하라고 화면에 적어 준다. 직접 알려 주려면:

  ```bash
  set AS_CHROME=D:\경로\chrome.exe        # Windows
  export AS_CHROME=/경로/chrome            # mac · 리눅스
  ```

  ⚠ 예전에는 경로가 **검사 파일 여덟 개에 박혀** 있었고, 그중 둘만
  환경변수를 봤다. 컴퓨터를 옮기면 하나만 고치고 일곱이 죽었다.
  로직 검사(`verify.mjs` 앞부분)는 크롬 없이도 돈다.
- 저장(세이브)은 없고 최고 점수만 브라우저 `localStorage` 에 남는다 — **컴퓨터마다 따로다.**
- ⚠ **`?v=` 를 올리지 않으면 배포해도 안 바뀐다.** `public/index.html` 안의
  `?v=` 를 전부 한 칸 올린다. `verify.mjs` 의 「캐시 무효화」가 안 올렸으면 잡는다.

### push 하면 자동 배포되게 하려면 (대시보드에서 한 번)

Cloudflare 가 Pages 를 Workers 로 통합해서, 깃 연동은 **Workers Builds** 다.
OAuth 로 GitHub 를 연결하는 절차라 명령줄로는 못 걸고 한 번은 눌러 줘야 한다.

1. dash.cloudflare.com → **Compute (Workers)** → `abyss-stairs` → **Settings** → **Build**
2. **Connect** 를 눌러 GitHub 계정(`comzoo123456789-ops`)을 연결하고 `abyss-stairs` 저장소 선택
3. 설정값 — **Build command 는 비워 둔다**(빌드 단계가 없다) ·
   Deploy command `npx wrangler deploy` · Root directory `/` · Production branch `main`

그 뒤로는 `git push` 만 하면 배포된다. 연결하기 전에도 `npx wrangler deploy` 로
언제든 손으로 배포할 수 있다 — 연동은 편의이고 필수가 아니다.

## 조작

| 키 | 동작 |
|---|---|
| ← ↑ ↓ → | 상하좌우 (**4방향** · 대각선은 없다) |
| (걷기) | **금화 · 물약 · 두루마리는 밟으면 저절로** 들어온다. **턴을 안 쓴다** |
| **Space** | 발 밑의 **장비** 줍기. **계단 위에서는 다음 층으로 내려간다** (G · `,` 도 받는다) |
| **가방에서 우클릭** | 버리기 — 자리 비우기. 발 밑에 물건이 있으면 **교환**된다 |
| 가방을 길게 누르기 | 버리기 (휴대폰 · 0.45초) |
| `>` | 계단에서 다음 층으로 (Space 와 같다) |
| **Q W E R** | 스킬 4칸 (레벨업·상점에서 모은다) |
| **F** | 원거리 공격 (활을 들었을 때) |
| `1`~`9` | 가방의 물건 쓰기 (목록 클릭도 가능) |
| `.` 또는 Numpad5 | 한 턴 쉬기 |
| `+` `-` | 지도 확대 1~3배 (`0` 이면 화면 크기에 맞춰 자동) |
| M | 효과음 켜기/끄기 |
| `?` | 도움말 (조작 패드 켜고 끄기도 여기) |

적에게 걸어 들어가면 공격이다(따로 공격 키가 없다).

**휴대폰 배치는 양손 엄지다.** 왼쪽 끝에 십자, 오른쪽 끝에 게임패드처럼 둥근
묶음 — 스킬 넷이 마름모, 가운데가 **통합 행동** 하나다. 가운데 단추는 지금 할 수
있는 것 하나만 띄운다(줍기 / 내려가기 / 쏘기). 고르는 순서는 Space 와 **같다**.

⚠ **패드는 "터치가 되는가" 가 아니라 "터치가 주된 입력인가" 로 띄운다.**
예전에 `maxTouchPoints > 0` 하나로 갈랐더니 터치 스크린이 달린 노트북이 전부
걸려서, 마우스가 있는데도 화면 아래 187px 를 패드가 먹고 지도 확대가 2배에서
1배로 떨어졌다. 둘 다 되는 기기는 **도움말(`?`)에서 켜고 끈다** — 고른 값은
기억한다. 손가락이 주된 기기에서는 그 단추를 감춘다(거기서는 늘 떠 있어야 한다).

⚠ **좁은 화면에서는 기록 패널이 없다.** 지나간 줄은 **장비 창(`I` · 「장비」)**
아래쪽 기록에서 되돌려 본다. 토스트는 다섯 개까지 3.6초만 뜬다 — 그것만 두면
놓친 줄을 다시 볼 방법이 없다.

⚠ **이동은 4방향이고 WASD·HJKL·YUBN·숫자패드는 없다.** 되살리지 말 것 —
그 키만 대각으로 가면 규칙이 두 개가 된다. 몬스터도 4방향이고 근접 판정도 4방향이다.

⚠ **Space 하나가 발 밑을 처리한다** — 물건이 있으면 줍고, 없는데 계단이면
내려간다(2026-09-18 사용자 지시 · 전에는 계단이 Enter 였다). Enter 는 더 안 받는다.
금화·물약·두루마리가 저절로 들어오게 된 뒤로 바닥에 남는 것은 **장비뿐**이지만
순서는 그대로다.
**순서를 뒤집지 말 것**: 계단 위에 물건이 있으면 먼저 줍는다. 내려가기가 먼저면
그 물건을 영영 못 줍는다. 칸을 눌러 제자리를 찍는 길(`tapTile`)과 순서가 같아야
한다 — 다르면 "어떤 때는 줍고 어떤 때는 내려간다" 가 된다.

⚠ **붙어 있는 적에게서 걸어서 물러나면 한 대 맞는다**(기회 공격). 그 적을 때리는
것은 해당되지 않고, 스킬로 자리를 옮기는 것도 안 걸린다. 왜 필요한지는 아래
「기회 공격」 을 볼 것 — 없으면 게임이 통째로 선택 사항이 된다.

## 빌드 — 정해진 틀이 없다

직업은 **출발점만** 정한다. 그 뒤로는 세 가지가 쌓여 각자 다른 캐릭터가 된다.

| 축 | 어디서 | 상한 |
|---|---|---|
| **능력치·스킬** | 레벨업마다 3개 중 하나 (`PERKS`) | 없음 — 같은 것을 계속 고를 수 있다 |
| **아이템 옵션** | 굴려 나오는 장비 (`AFFIXES` 12종) | 없음 — 같은 옵션이 셋 붙으면 셋만큼 세진다 |
| **스킬** | 레벨업 또는 상점 (`SKILLS` 10종 · 4칸 · 4단계) | 4칸까지, 단계는 4단까지 |

⚠ **옵션에 상한을 두지 말 것.** 상한을 두면 결국 한 가지 최적해로 수렴하고, 그러면
빌드를 고민할 이유가 사라진다(Risk of Rain 2 가 무한 중첩으로 재미를 만드는 이유).
균형은 플레이어를 깎는 대신 **몬스터 쪽 기울기**(`scaleAt`)로 잡는다.

⚠ **보스는 층 배수를 안 받는다.** 보스에도 곱하면 기울기 하나가 "잡몹 난이도" 와
"보스 난이도" 를 동시에 흔들어 조정이 불가능해진다 — 실측에서 기울기를 0.16 → 0.30
으로 올린 것만으로 승률이 95% → 10% 로 떨어졌고 그 대부분이 보스층 사망이었다.
손잡이 하나에는 한 가지만 달려 있어야 한다.

### 아이템

등급이 색이다: <b>일반</b>(흰) · <b>고급</b>(파랑, 옵션 1) · <b>희귀</b>(노랑, 옵션 2) ·
<b>유물</b>(주황, 옵션 3). 무기는 6종(검·도끼·단검·지팡이·활·창)이고 종류마다 성격이 다르다.

이름은 `관형격 + 형용사 + 기본명` 으로 조립한다 — "역병의 곪은 비늘 갑옷".
⚠ 한국어는 수식어가 **모두 앞**에 온다. 접미를 뒤에 붙였더니 "약초사의 은장 지팡이
처형의" 같은 비문이 나왔다. `AFFIXES` 의 `pre` 는 형용사형, `suf` 는 관형격으로
통일하고 섞지 말 것("의" 가 겹친다).

### 상점

2층마다 상인이 선다. 아이템 5개 + 스킬 2개를 팔고, 가방을 팔 수도 있다.
⚠ **상인은 길을 막지 않는다.** 예전에는 막았고 밟으면 턴을 안 쓴 채 창만 열었다 —
계단 가는 길이 상인을 지나갈 때 열고 닫기를 무한 반복했다(실측: AI 120판 중 65판이
그렇게 갇혔다). 사람에게도 나쁘다. 지금은 밟으면 **들어가면서** 창이 열린다.

## 세계관 — 「지워지는 이름」

도시 아래 심연은 **매일 지형이 다시 배치된다.** 그 밑의 군주가 지상의 기억을 먹고 있어서,
내려간 사람은 돌아오지 않을 뿐 아니라 **이름이 지워진다.** 가족도 그를 잊는다. 관리소
장부에는 이름 없이 **몇 층까지 갔는가**만 남는다.

이 설정은 장식이 아니라 **시스템을 설명하기 위한 것**이다:

| 시스템 | 설정상 이유 |
|---|---|
| 매번 던전이 새로 생성됨 | 심연이 매일 다시 배치된다 |
| 죽으면 끝 (세이브 없음) | 죽으면 이름이 지워진다 |
| 최고 점수만 남음 | 장부에는 층수만 적힌다 |
| 물약이 미식별 | 심연에서 나온 것에는 라벨이 없다 |
| 판마다 다른 인물 | 매번 **다른 지원자**가 내려간다 |

마지막 줄이 핵심이다. 한 영웅이 계속 부활하는 게 아니라 **매 판이 다른 사람**이라
영구 죽음이 설정과 어긋나지 않는다. 세 인물은 모두 **지워진 이름** 때문에 내려간다 —
그 사연이 생김새에 들어 있다(방패에 새긴 홈 · 품속 장부 조각 · 반쯤 지워진 이름).

⚠ 문구를 고칠 때 이 결을 깨지 말 것. 죽을 때의 "장부에는 층수만 적힐 것이다" 와
승리할 때의 "먹힌 이름들이 돌아온다" 가 이 게임의 처음과 끝이다.

## 설계에서 지킬 것

**점검 도구의 지문 안에는 백틱을 쓰지 않는다.** `tools/*.mjs` 는 화면에 보낼 코드를
템플릿 문자열로 들고 있다. 그 안에 한글 주석을 달면서 선택자를 백틱으로 감싸면
문자열이 **거기서 닫힌다.** 파일은 문법 검사를 통과하고, 실행할 때
`.acts is not a function` 처럼 **원인과 상관없는 말**로 죽는다. 하루에 네 번 겪었다.
지문 안에서는 `.acts` 처럼 그냥 적는다.

**같은 줄에서 `heredoc` 으로 정규식을 쓰지 않는다.** 셸이 백슬래시를 먹어
`\s` 가 `\s` 로, `\(` 가 `(` 로 저장된다 — 정규식이 조용히 틀리거나
"Unterminated group" 으로 죽는다. 정규식이 든 파일은 Write 도구로 쓴다.


**밸런스는 눈대중으로 만지지 않는다.** `tools/verify.mjs` 가 층을 정리하며 내려가는 AI 로
직업마다 판을 돌려 승률을 잰다. 기준은 **직업별 35~65%** 이고 **직업 사이 격차 25%p
이하**다. 그 AI 는 길찾기가 완벽하고 전 층을 정리하므로 **사람 승률은 이보다 훨씬 낮다**.

**한 직업이 압도하면 나머지는 장식이다.** 도적이 `atkPerLevel: 3` + 쿨 4턴 원거리 투척
조합으로 **200판 전승(100%)** 이었다. 화력을 그대로 두고 `defPerLevel: 0` · `hpPerLevel: 8`
로 맷집만 깎아 유리대포로 만들었다 — 수치를 깎는 것보다 **성격을 가르는 쪽**이 낫다.

**피해 공식은 비율 감쇄다**(`Game.prototype.roll`). `공격 − 방어` 로 두면 방어가 공격을
넘는 순간 피해가 1 로 떨어지는 절벽이 생겨 조정이 불가능해진다 — 실측에서 레벨당 방어
+1 을 +0.5 로 줄인 것만으로 **승률이 72.7% → 11.7%** 로 뒤집혔다.

**1층은 쥐만 나오는 연습 층이다.** 고블린을 섞었더니 300판 중 32판이 1층에서 끝났다.
시작하자마자 죽는 게임은 다시 안 하게 된다. 함정도 1층에는 0개다.

**미식별 물약에는 나쁜 것이 섞여 있어야 한다.** 전부 이로우면 "일단 다 마신다" 가
정답이 되어 선택이 사라진다. 그래서 독 물약이 있다. 겉모습은 **판마다 다시 섞는다** —
고정이면 두 번째 판부터 모두가 식별된 셈이다.

**보물방은 벽이 아니라 문으로 둘러싼다.** 벽으로 막으면 들어갈 길이 없어 아이템이 영영
안 닿는다(생성기가 만든 방은 복도가 한 방향에서만 온다). `verify.mjs` 가 보물방마다
"바깥에서 걸어 들어갈 수 있는지" 를 BFS 로 확인한다.

**객체 리터럴에 같은 키를 두 번 쓰지 말 것.** 몬스터에 `def`(정의)와 `def`(방어력)를
같이 뒀다가 뒤엣것이 이겨 `m.def.xp` 가 `undefined` 가 됐고, **경험치가 NaN 이 되어
레벨업이 영영 안 됐다.** 문법 오류가 아니라 조용히 틀린다 — 지금 정의는 `src` 다.

**사이드바 패널은 `flex-shrink: 0` 이다.** flex 기본값이 줄어드는 것이라 사이드바에
max-height 가 걸리면 상자만 찌그러지고 자식이 밖으로 새어 나와 겹친다(실측 390px 에서
공격·방어·금화·처치 칸이 통째로 안 보였다). **이 규칙을 `@media (max-width:900px)` 안에만
두면 안 된다** — 1440 터치 화면에도 max-height 가 걸려 같은 결함이 남는다.

**터치 패드 표시를 `@media (pointer: coarse)` 한 곳에만 걸지 말 것.** 그 판정이 어긋나는
기기에서 패드가 안 뜨는데 휴대폰에는 키보드가 없다 — **조작 수단이 아예 없어진다.**
지금은 ① 미디어쿼리 ② JS 터치 감지 ③ 사람이 켜는 토글 셋 중 하나만 맞아도 뜬다.

**한 칸 32px = 스프라이트 32px 그대로다(확대 없음).** 16×16 을 2배로 늘려 쓰던 때보다
픽셀이 4배라 얼굴·장식이 들어간다. 확대해 쓸 때는 **정수배**여야 한다(직업 카드는 3배).
⚠ 24px 로 뒀던 시절엔 맵이 화면에 거의 다 들어와 카메라가 따라다니지 못했다(밝은 픽셀 2.5%).

**도트는 문자 그림이 아니라 원시 도형으로 쌓는다**(`sprites.js` 의 `art`).
32줄 × 32칸을 문자로 적으면 한 픽셀 옮기려고 줄 전체를 다시 세야 해서 사실상 못 고친다.
도형으로 쌓으면 숫자 하나만 고쳐 위치를 옮길 수 있고, **윤곽선(`outline`)과 명암(`rim`)을
마지막에 한 번에** 입힐 수 있다 — 그게 도트가 깔끔해 보이는 이유다.

⚠ **그리는 순서가 곧 레이어다.** 깃털을 투구보다 먼저 그렸다가 투구 돔이 위로 덮어
**깃털이 통째로 사라졌다**(빨간 점 하나만 남았다).

⚠ **32px 로는 잘 그렸는지 판단이 안 된다.** 스프라이트를 6배로 펼쳐 한 장에 찍어 보고
고친다(scratchpad `sheet.mjs`). 그걸로 잡은 것들: 전사가 흰 덩어리 · 도적이 녹색 덩어리 ·
트롤은 머리와 몸이 붙은 한 덩어리 · 군주 망토가 **형광 분홍** · 오크 도끼가 회색 깃발.

⚠ **바닥 변종은 이음선을 다른 자리에 둔다.** 처음엔 모든 변종이 비슷한 높이에 가로
이음선을 가져서, 깔아 보니 바닥 전체가 **가로 줄무늬**로 보였다(돌이 아니라 나무 판자).
그리고 판석은 타일 가장자리에 붙여야 한다 — 안쪽으로 들이면 32px 격자가 눈에 드러난다.

**색 입힌 스프라이트는 오프스크린에서 굽는다.** 메인 캔버스에 `source-atop` 으로 칠하면
그 합성이 "이미 그려진 곳" 전체에 걸려 **바닥까지 물든다**(배경을 불투명하게 칠해 둔다).

**이동 애니메이션은 규칙과 분리한다.** 규칙은 한 칸씩 **즉시** 움직이고(턴제니까) 화면만
그 뒤를 따라간다. 렌더러가 논리 좌표를 보고 "지금 보이는 자리"를 쫓아가므로 규칙 코드를
한 줄도 안 고치고 붙는다(검사도 그대로 돈다).

⚠ **애니메이션이 끝날 때까지 규칙을 붙잡으면 안 된다** — 연타가 밀려 "눌렀는데 안 움직인다"
가 된다. 한 칸 115ms 이고, 그 안에 또 누르면 보이는 자리에서 새 걸음을 시작한다.

⚠ **한 칸을 넘는 이동은 보간하지 않는다**(순간이동·층 이동). 지도 절반을 미끄러져 가면
무엇이 일어났는지 알 수 없다 — 맨해튼 2칸 이상이면 스냅한다.

⚠ **가만히 있을 때는 프레임 고리를 돌리지 않는다.** 턴제 게임이 60fps 로 배터리를 태울
이유가 없다 — `draw(dt)` 가 "아직 움직일 것이 남았는가"를 돌려주고 그때만 다음 프레임을
예약한다. 흔들림·붉은 막도 프레임 수가 아니라 **시간(dt)** 기준으로 줄어야 한다.

⚠ 공격은 **좌표가 안 변해서** 렌더러가 알 수 없다. 규칙이 `game.fx()` 로 신호를 쌓고
렌더러가 비워 간다(찌르기·피격 빛). 화면이 없어도 쌓이고 말 뿐이라 검사가 안 깨진다.

⚠ 걸음 프레임은 **몸통을 한 벌 더 적지 않는다.** `["f", n]` 필터로 다리만 갈라 적는다 —
그림을 통째로 복사하면 몸을 고칠 때 두 곳을 고쳐야 해서 반드시 어긋난다.

**누르고 있을 때의 걸음은 우리가 센다.** OS 키 반복은 30ms 간격이라 그대로 받으면
화살표를 쭉 누르는 순간 캐릭터가 지도를 슝 건너간다(사용자 신고: "너무 빨라").
`e.repeat` 는 **버리고** 걸음 간격(`STEP_MS`)으로 직접 반복한다.
⚠ 창을 떠나면 `keyup` 을 못 받는다 — `blur` 에서도 멈춰야 혼자 걷지 않는다.

**기록 패널은 사이드바 바닥에 고정한다.** 상태창이 길어지자(스킬 4칸·빌드 요약)
기록이 아래로 밀려 화면 밖에 있었다 — 사용자 신고: "기록이 실시간으로 안 따라온다".
위쪽(상태창+가방)만 스크롤 영역으로 두고 기록은 못박는다. 그리고 최근 메시지를
**캔버스 위에도** 띄운다(전투 중 눈은 사이드바가 아니라 지도에 있다).
⚠ 토스트가 3.6초간 사라지는 동안은 프레임이 도는 것이 정상이다 — "유휴 시 정지"
검사는 그보다 길게 기다려야 한다(600ms 만 기다려 오진했다).

**모바일 버튼은 `touch-action: manipulation` + `touchstart` 로 처리한다.**
`click` 만 쓰면 ① 브라우저가 더블탭 여부를 보려고 ~300ms 기다려 연타가 끊기고
② 연달아 누르면 **더블탭으로 판정해 화면이 확대된다**(실제 신고였다).
viewport 의 `user-scalable=no` 는 iOS 가 무시하므로 CSS 쪽이 본체다.
⚠ `touchstart` 에서 `preventDefault` 한 뒤에는 따라오는 합성 `click` 을 막아야
한 번 누른 것이 두 번 먹지 않는다.

**`data.js` 의 설명 문구는 HTML 로 그대로 들어간다.** `**강조**` 를 적으면 별표가 그대로
보인다. `verify.mjs` 가 마크다운 기호를 잡는다(실제로 한 번 새어 나갔다).

**몬스터 길찾기는 턴당 한 번 만드는 거리 지도(흐름장)다**(`buildFlow`). 몬스터마다
탐욕적으로 한 걸음 고르는 방식은 **4방향에서 깨진다** — 두 축이 다 막히면 아무 방향으로나
갔다가 다음 턴에 되돌아와 제자리에서 떨고, 쫓는 쪽과 거울처럼 오가며 영원히 안 만난다
(실측: 두 칸을 **6만 턴** 왕복하며 해골 1마리를 못 잡음). 값이 **줄어드는 칸만** 고른다 —
같거나 커지는 칸을 허용하면 그 순환이 돌아온다. 반경(`FLOW_MAX`)을 잘라 두어 멀리 있는
놈은 못 쫓아온다(도망이 여전히 통한다).

**버리기는 발 밑에 물건이 있으면 교환한다.** 거절하면 막다른 골목이 생긴다 — 가방이 꽉 찬
채 물건 위에 서 있으면 주울 수도 버릴 수도 없어서, 자리를 비우려고 만든 기능이 정작
필요한 순간에 안 된다. 교환으로 두면 한 칸에 물건이 둘 쌓이는 일도 없다.

**조사는 `josa()` 로 붙인다.** `이름 + " 을(를)"` 로 두면 "굶주린 쥐 을(를) 주웠다" 가 된다.

**소리는 없어도 게임이 돌아야 한다.** `game.js` 는 `if (global.SFX)` 로 감싸고 `sound.js` 는
모든 호출을 `try` 로 감싼다. 그래서 `verify.mjs` 는 `sound.js` 를 안 올리고도 로직을 돌린다.
⚠ AudioContext 는 **첫 소리 요청 때** 만든다 — 미리 만들면 자동재생 차단에 걸린다.

**화면은 반드시 실제로 띄워서 확인한다.** 로직 검사가 통과해도 캔버스가 0px 일 수 있고,
콘솔 오류 0 건을 확인하지 않으면 `try/catch` 에 삼켜진 예외로 반쪽만 로드된다.
⚠ "키가 안 먹는다" 를 **로그 줄 수**로 판정하지 말 것 — 그냥 걷는 것은 로그를 안 남긴다
(그래서 멀쩡한 입력을 고장으로 오진했다). 좌표와 턴을 본다.
⚠ 능력 쿨다운은 **브라우저 검사로 확인되지 않는다** — 1층엔 붙을 적이 없어 거절만 나온다.
`verify.mjs` 가 적을 세워 놓고 피해·쿨 설정·거절·회복을 직접 잰다.
⚠ 그 검사에서 **적을 치우고 쉬어야 한다.** 옆에 세워 둔 채 8턴을 쉬게 했더니 체력 36인
마법사가 맞아 죽어 `act()` 가 멈췄고, "쿨다운이 안 풀린다" 로 오진했다.

### 화면을 좁은 쪽에 맞출 때 (2026-09-18)

휴대폰에서 "화면이 좁아 조작이 힘들다" 는 신고를 받고 고친 것들. **자리를 무엇으로
정하는지**가 전부였다.

- **체력·경험은 맨 위 한 줄(`#hud`)에 못박는다.** 전에는 오른쪽 사이드바 안에만 있어서
  좁은 화면에서는 **스크롤해야 체력이 보였다** — 죽기 직전인 걸 모르고 한 칸 더 걷는다.
  ⚠ 같은 값을 사이드바에도 남겨 두지 말 것(한쪽만 고쳐져 어긋난다). 막대를 옮긴 뒤
  `drawStats` 에서는 지웠고, 중복이 된 "누구인가" 줄도 좁은 화면에서는 접는다.
- **기록 패널은 좁은 화면에서 아예 없앤다.** 98px 를 줘 봤지만 그만큼 캔버스와 조작
  패드가 눌렸다. 같은 내용은 **캔버스 위 토스트**가 띄우고 3.6초 뒤 사라진다.
  ⚠ 그래서 점검기의 "기록이 보이는가" 는 **화면 폭에 따라 다른 것을 재야 한다**
  (넓으면 패널 사각형, 좁으면 쌓인 기록 줄 수). 안 갈라 두면 오진한다.
- **감추는 이유는 '터치' 가 아니라 '좁음' 이다.** `@media (pointer: coarse)` 만으로 걸면
  터치 노트북(1440)에서도 기록이 사라진다 — 거기는 자리가 넉넉하다. 폭과 함께 건다.
- ⚠ **`body.is-touch .side` 가 미디어쿼리를 덮는다.** 클래스가 붙은 선택자가 특정도에서
  이기므로, `@media (max-width:900px)` 안에서 27vh 로 줄여도 **실측이 그대로 30vh** 였다
  (사이드바 253px 고정). 넓은 화면 전용(`min-width: 901px`)으로 가뒀다.
  같은 종류의 함정을 `.side > .panel { flex-shrink: 0 }` 에서도 겪었다 — **조건을 폭이
  아니라 의도에 맞게 건다.**
- **조작 패드 자리는 flex-wrap 에 맡기지 않는다.** 사용자가 배치를 지정했다(십자 맨 왼쪽 ·
  줍기·쏘기·내려가기 한 줄 · 그 아래 QWER). 줄바꿈에 맡기면 폭에 따라 십자가 가운데로
  밀리고 행동 버튼이 세로로 선다 — **엄지가 닿는 자리가 화면마다 달라진다.**
  `grid-template-columns: auto minmax(0,1fr)` + `grid-area` 로 못박았다.
  ⚠ `.pad` 를 grid 로 바꿀 때 **켜는 규칙 전부**를 `display: grid` 로 함께 고칠 것
  (한 곳만 고치면 다른 조건으로 뜬 화면이 옛 배치로 나온다).
- **헤더 버튼(소리·조작 패드·도움말)을 지웠다.** 390px 에서 제목과 폭을 다투다 정작
  상태가 들어갈 자리가 없었다. 기능은 키로 남는다(M · ?).
  ⚠ 조작 패드 토글을 지울 때 **저장된 "꺼짐"(`localStorage.rl_pad`)도 지워야 한다** —
  남겨 두면 그 브라우저에서는 패드가 영영 안 뜨는데 되돌릴 버튼이 없다(휴대폰에는
  키보드가 없으므로 조작 수단이 통째로 사라진다).

### 아이템 그림은 종류마다 달라야 한다

무기를 6종(검·도끼·단검·지팡이·활·창)으로 나눠 놓고 **그림은 전부 `sword` 하나를
공용으로 썼다.** 바닥에 떨어진 것이 도끼인지 활인지 알 수 없으니 종류를 나눈 의미가
사라진다(사용자 지적). 이제 `it.sprite = wk.id` 이고 보조 장비는 `shield` 다.

- ⚠ **검을 축소해서 단검으로 쓰면 안 된다.** 처음엔 길이만 2/3 로 줄였는데 6배로 늘려
  보니 검과 똑같았다. 32px 에서는 길이 비율이 아니라 **덩어리 모양**으로 읽힌다 —
  날을 절반으로 자르고 폭과 코등이를 키워야 갈린다.
- **등급은 바닥에서도 보인다.** 일반이 아닌 장비에는 등급 색 방사 그라디언트를 깐다.
  ⚠ 일반에는 깔지 않는다 — 전부 빛나면 아무것도 눈에 걸리지 않는다.
- ⚠ **구획을 바꿀 때 표시 문장은 그 구획에만 있는 것으로 잡을 것.** `'  /* 지팡이 —'` 로
  끝을 잡았더니 **마법사 스프라이트의 지팡이 주석**이 먼저 걸려(파일 앞쪽) 끝이 시작보다
  앞이 되었고, 한 덩어리가 그대로 복제돼 문법 오류가 났다.

### 검사 순서가 제품을 오진하게 만든다

`--play` 로 끝까지 돌린 뒤에는 **종료 화면이 키를 다 먹는다**(Enter·R 만 받는다).
그 상태로 뒤의 검사를 이어 돌렸더니 도움말(? 키)·연타 확대·누르고 걷기가 전부 빨갰다 —
제품이 아니라 검사 순서가 문제였다. 지금은 끝낸 뒤 `__start` 로 한 판을 새로 켠다.

### 캐시 무효화를 빠뜨리면 아무 단서가 없다

`public/js`·`css` 를 고치고 `index.html` 의 `?v=` 를 안 올리면 **이미 접속한 사람에게는
옛 파일이 그대로 나간다.** 배포는 성공하고 화면 검사도 전부 통과한다(점검기는 늘 새
브라우저라 캐시가 없다) — 정작 쓰던 사람만 안 바뀐다. 구역 배포에서 실제로 한 번 빠뜨렸다.

`node tools/cache-check.mjs` 가 네 가지를 본다(verify 가 문법 검사 바로 뒤에 돌린다):
① 모든 js/css 참조에 `?v=` 가 붙었는가 ② 값이 하나로 통일됐는가 ③ 참조한 파일이
실제로 있는가(오타 난 경로는 404 로만 드러난다) ④ 마지막 커밋 이후 js/css 가 바뀌었는데
`index.html` 은 그대로인가.

### 구역 — 내려가는 느낌 (2026-09-18)

1층부터 10층까지 돌벽 하나로 똑같이 생겼었다. 열 층을 내려가는데 **내려가는 느낌이 없다** —
숫자만 올라갈 뿐이었다. 두 층씩 묶어 다섯 구역으로 가른다(`data.js` 의 `ZONES`).

| 층 | 구역 | 장식 |
|---|---|---|
| 1–2 | 관리소 아래 | 나무 상자 · 꺼진 등불 |
| 3–4 | 물이 든 계단실 | 물웅덩이 · 이끼 |
| 5–6 | 이름의 도서관 | 책더미 · 흩어진 종이 |
| 7–8 | 뼈 무덤 | 뼈무더기 · 해골 |
| 9–10 | 군주의 방 | 핏자국 · 핏줄 |

- ⚠ **구역은 색·장식·문구만 바꾼다. 규칙은 하나도 안 건드린다.** 여기서 몬스터나
  난이도를 함께 건드리면 손잡이 하나에 두 가지가 달려 균형 조정이 불가능해진다
  (보스 배수에서 이미 겪었다 — 0.16 → 0.30 하나로 승률이 95% → 10% 가 됐다).
- ⚠ **밝기를 구역마다 크게 바꾸지 말 것.** 바닥이 어두워지면 그 위의 도트가 안 보인다 —
  **색상만 돌리고 명도는 붙잡는다**(UI 팔레트를 갈색으로 돌릴 때와 같은 규칙).
  ⚠ 군주의 방은 처음 값이 **분홍**으로 읽혔다(6배로 늘려 보고 알았다) — 채도를 내렸다.
- ⚠ **타일 캐시 열쇠에 구역 id 를 반드시 넣는다.** 안 넣으면 1층에서 구운 타일이
  10층까지 그대로 쓰여 색이 안 바뀌는데, 원인이 화면에 전혀 안 드러난다.
- 층 표시(배지)에 구역 이름을 적고, 눈금 10칸을 **구역이 바뀌는 자리에서 띄운다** —
  그래야 열 칸이 다섯 구역으로 읽힌다(그냥 열 칸이면 그냥 열 칸이다).
- 구역에 처음 들어설 때만 그 구역의 문구를 띄운다(열 층이 전부 "지형이 어제와 다르다" 였다).

**장식(`lv.props`)은 규칙에 아무 영향이 없다.** 막지도 않고 밟아도 아무 일도 없다.
함정처럼 지형과 **별도 층**에 둔다(지형에 섞으면 원래 지형을 잃는다).

- ⚠ **아이템처럼 보이면 안 된다.** 주우러 걸어갔는데 아무 일도 없으면 고장으로 느낀다.
  그래서 장식에는 검은 테두리(`outline`)를 **두르지 않는다** — 이 게임의 아이템은
  전부 테두리가 있어서 그것만으로 눈이 갈린다.
- ⚠ **그렇다고 흐리게 두면 아예 안 보인다.** 처음에 바닥과 비슷한 색으로 그렸더니
  실측 픽셀 차이가 **100 안팎**이었다(화면에서 찾을 수가 없었다). 시야 밖 칸은 30%
  투명도로 그려지므로 **바닥보다 확실히 밝아야** 그때도 읽힌다. 테두리 없음 + 밝기
  차이 — 둘을 함께 써야 "바닥에 있는 흔적" 으로 읽힌다.
  ⚠ "안 보인다" 를 눈으로 단정하지 말 것. 장식을 지운 프레임과 **픽셀을 비교**해야
  '안 그려진다' 와 '그려지는데 흐리다' 가 갈린다(scratchpad `propcheck.mjs`).
- ⚠ 계단·함정 칸은 피한다. 덮으면 계단을 못 알아보거나 드러난 함정을 밟는다 —
  규칙은 그대로인데 **화면만 거짓말한다**. 밀도는 바닥 칸의 4%(실측 3.8%).
- ⚠ 색 값 오타(`#437competitors`)가 하나 섞여 들어갔었다. 문법 검사로는 안 잡히고
  그 색만 조용히 안 그려진다 — `"#..."` 를 전부 6자리 hex 로 대조하는 검사를 둔다.

**검사에서 또 배운 것 — 기능을 늘리면 검사의 전제가 낡는다**

- ⚠ `__peek()` 에 `cooldown` 이 **없었다.** 그래서 "스킬이 터졌나" 를 가르는
  `cd > 0` 이 늘 false 였고 **성공 갈래가 죽은 코드**였다 — 스킬이 실제로 터진 판이
  오히려 실패로 읽혔다(마법사 검사가 가끔 빨개진 진짜 이유).
- ⚠ **거절을 문구로 맞히지 말 것.** `/닿는|없다|준비/` 로 봤는데 실제 문구가
  "허공에서 흩어졌다." 라 안 걸렸다. 거절도 행동이므로 **기록이 한 줄 늘었는지**로 본다 —
  문구가 바뀌어도 그대로다.
- ⚠ 레벨업 검사가 능력치 비교였는데, **유물은 규칙을 바꾸므로 `stats()` 가 그대로다** —
  유물이 선택지에 섞이자 "고른 뒤 변화 없음" 으로 빨개졌다. 제품이 아니라 검사의
  전제가 낡은 것이었다. 지금은 갈래 넷(능력치·새 스킬·스킬 강화·유물)이 **전부**
  반영되는지 120회로 따로 센다.

### 유물 — 숫자가 아니라 규칙을 바꾼다 (2026-09-18)

특성(PERKS)은 **숫자**를 올린다(공격 +3, 치명 +6%). 그것만으로는 판이 매번 비슷하다 —
쌓이는 값이 다를 뿐 하는 짓이 같기 때문이다. 유물은 **규칙 자체**를 바꾼다.

`data.js` 의 `RELICS` 10종 · 효과는 `game.js` 의 **정해진 자리에서만** `hasRelic()` 으로
읽는다(어디서 읽는지 목록이 `hasRelic` 주석에 있다 — 흩어 두면 어떤 이상 동작이 어느
유물 때문인지 추적이 안 된다).

- **유물마다 대가가 있거나, 없으면 조건이 좁아야 한다.** 그냥 좋기만 하면 매번 같은 것을
  고르게 되어 특성과 다를 바가 없다(DCSS 의 "압도적인 하나를 없앤다" 와 같은 이유).
- **같은 유물을 두 번 주지 않는다** — 배수가 겹치면 균형이 통째로 무너진다.
- 레벨업 선택지에 `RELIC_CHANCE`(0.34)로 한 자리를 내주고, 상인이 절반쯤 하나를 갖고 있다.
  ⚠ 특성·스킬과 같은 통에 넣으면 유물이 10개뿐이라 후반에 거의 안 나온다 — **따로 뽑는다.**
- ⚠ **유물은 가방을 차지하지 않는다.** 칸을 먹으면 "좋은데 자리가 없어 못 산다" 가 되어
  유물의 뜻(규칙을 바꾼다)이 자리 관리 문제로 바뀐다.

**균형은 짐작하지 말고 잰다.** 유물을 넣자 직업 격차가 6.7%p → 18.3%p 로 벌어졌다.
scratchpad `relicsweep.mjs` 가 **유물 하나만 쥐여 준 판**을 기준선과 비교한다(레벨업에서
유물이 안 나오게 막아 다른 유물이 섞이지 않게 한다 — 안 그러면 무엇이 무엇을 흔들었는지
알 수 없다). 그렇게 세 개를 잡았다:

| 유물 | 처음 | 실측 | 고친 것 |
|---|---|---|---|
| 피를 먹는 검 | 처치당 최대 체력 +2 | **+36%p** (전 직업) | 최대 체력을 불리는 것을 그만두고 **회복**으로. 최대 체력이 천장이라 저절로 묶인다 |
| 남의 기억 | 상인이 오지 않는다 | **−14~−20%p** | 상점은 빌드를 만드는 자리라 조금만 건드려도 판이 무너진다 — **대가를 없애고** 값을 낮췄다 |
| 군주의 눈 | 몬스터가 전부 깨어 있다 | 셰라 −12.5%p | 대가를 **감지 범위**로(8칸 → 16칸). 물러서서 싸우는 직업에게 그냥 나쁜 유물이었다 |

- ⚠ **상한을 낮추는 것으로는 안 되는 경우가 있다.** 피를 먹는 검을 +1·상한 50 으로 묶어도
  +16~22%p 였다 — 체력 기반이 직업마다 달라(62 vs 38) **같은 상한이 배수로는 전혀 다른
  값**이기 때문이다. 그럴 때는 수치가 아니라 **성격**을 바꾼다.
- ⚠ N=80 의 잡음이 약 ±10%p 다. 그 안의 차이를 쫓아 손대면 잡음을 조정하는 셈이 된다.
- 지금: 45.0 / 45.0 / 58.3%, 격차 13.3%p(기준 28%p 이하).

**안전장치를 함께 잰다**(verify "유물" 12항목). 빠뜨리면 조용히 무너지는 것들이다:
- 「빈 이름」(치명타 즉사)은 **보스에 안 통한다** — 통하면 10층이 한 방으로 끝난다.
- 「두 번 새기는 붓」은 **내가 거는 것만** 길어진다 — 안 가르면 내 유물이 나를 때린다.
- 「가시 갑옷」의 반사는 `damage()` 를 그대로 쓴다 — 직접 hp 를 깎으면 `kill()` 을 안 타서
  시체만 남고 경험치·금화가 사라진다.
- 층에 내려설 때 듣는 유물은 **몬스터·함정·상인을 다 배치한 뒤**에 적용한다 — 앞에 두면
  군주의 눈이 아직 없는 몬스터를 깨우고, 계단의 기억이 옛 최대 체력으로 회복한다.
- 유물을 얻는 순간 **그 층에 바로 듣는 것은 그 자리에서 적용**한다(군주의 눈·남의 기억) —
  안 하면 "주웠는데 아무 일도 없다" 가 되어 다음 층까지 고장으로 느낀다.

### 하루의 장부 (일일 던전 + 공유판 · 2026-09-18)

세계관이 장부다 — "관리소 장부에는 이름 없이 **몇 층까지 갔는가**만 남는다". 그러면
공유판이 곧 장부 한 줄이다. 억지로 붙인 유행이 아니라 세계관이 원래 요구하던 것이다.

Rogule(7일 게임잼 작품)이 Wordle 형식을 던전에 붙여 웹에서 터졌고, 만든 사람이 직접
꼽은 성공 요인이 **공유판**이었다. 핵심은 "모두가 같은 던전" 이다 — 씨앗이 사람마다
다르면 비교가 성립하지 않아 공유할 이유가 없어진다.

```
public/js/daily.js        날짜 · 씨앗 · 공유 글자 · 장부 저장  (DOM 을 안 건드린다)
tools/daily-check.mjs     하루 한 번 잠금을 브라우저에서 밟는다 (17개 항목)
verify.mjs "일일 씨앗"    씨앗이 날마다 흩어지는가 · 한국시간 경계
```

- **기준 시간대를 한국(UTC+9)으로 못박는다.** 브라우저 시간대에 맡기면 같은 날짜에
  사람마다 다른 던전이 나와 "모두가 같은 던전" 이 깨지고, 시간대를 옮겨 다니며 하루를
  여러 번 돌 수도 있다. ⚠ `getFullYear()` 같은 지역 함수를 쓰면 안 된다 — 그게 곧
  브라우저 시간대다. UTC 로 9시간 더한 뒤 `getUTC*` 로 읽는다.
- ⚠ **날짜를 그대로 숫자로 쓰면(20260918) 이웃한 날의 던전이 닮는다** — 씨앗 RNG 가
  낮은 비트부터 쓰기 때문이다. FNV-1a + xorshift 로 흩어 놓는다. 검사가 1년 365일의
  중복과 "이웃 씨앗의 xor 에서 켜진 비트가 8개 미만" 인 경우를 센다(둘 다 0이어야 한다).
- ⚠ **오늘 몫은 '시작할 때' 쓴다.** 끝날 때 적으면 구멍이 생긴다 — 판이 나쁘게 흘러갈 때
  새로고침하고 다시 시작하면 되므로 "하루 한 번" 이 말뿐이 된다. **실제로 그 상태였고
  검사로 잡았다.** 그래서 `begin()` 이 자리를 먼저 잡고 `finish()` 가 채운다.
  - 대가는 **중단한 판도 장부에 남는 것**이다. 그래서 시작 화면에서 분명히 알린다
    ("시작하면 오늘 몫을 쓴다"). 대가를 숨기면 고장으로 느낀다.
  - 중단한 판을 "지워졌다" 라고 적으면 거짓이다 — 죽은 게 아니라 그만둔 것이다.
    `open` 이면 "N층에서 멈췄다 (중단)".
  - 끝난 뒤 `finish()` 를 또 불러도 **닫힌 자리는 안 바뀐다**. 안 막으면 좋은 기록으로
    갈아치울 수 있다.
- ⚠ **이 잠금은 브라우저 안에서만 유효하다**(localStorage). 지우면 다시 할 수 있다.
  서버로 막으려면 계정이 필요하고, 그건 순위표를 만들 때 함께 할 일이다 — 지금은 이르다.
  **점수를 브라우저가 계산하므로 서버로 옮겨도 위조를 못 막는다.**
- ⚠ **`localStorage` 는 막힐 수 있다**(시크릿 모드). 읽기·쓰기를 전부 `try` 로 감싸고
  실패하면 "오늘 안 했다" 로 본다 — 못 하게 막는 것보다 낫다. 검사가 저장 없는 환경을 민다.
- ⚠ **공유 글에 `location.host` 만 적으면 카톡·디스코드에서 링크가 안 걸린다** — 그러면
  공유판을 본 사람이 게임에 못 온다(만든 이유의 절반이 사라진다). `location.origin` 이다.
- ⚠ **장부 막대는 이모지다.** 색 이모지 글꼴이 목록에 없으면 기기에 따라 네모(두부)로
  붙어 공유판이 통째로 망가진다 — `.ledger-text` 는 고정폭보다 **먼저** 이모지 글꼴을 찾는다.
  그리고 플랫폼마다 있는 것만 쓴다(🟨 ⬛ 🟥 👑). 칸 수는 코드포인트로 센다 —
  `length` 로 세면 서로게이트 쌍 때문에 20이 나온다.
- ⚠ **이모지 막대는 줄바꿈되면 모양이 망가진다** — `white-space: pre` + 가로 스크롤.
- ⚠ **끝 화면을 닫은 뒤에도 장부를 베낄 수 있어야 한다.** 시작 화면의 "오늘 몫" 알림에
  같은 공유판과 베끼기 단추를 둔다 — 없으면 공유할 방법이 사라진다.
- **자유 탐사도 공유할 수 있다.** 머리글만 다르다 — "모두 같은 던전" 이 아닌 판을
  「N월 N일의 장부」 라고 적으면 거짓이 된다. 씨앗을 함께 적어 같은 던전을 다시 만들 수 있다.
- ⚠ 점검기의 `__start` 기본값은 **자유 탐사**다. 일일로 켜면 두 번째 검사부터 "오늘 몫 끝"
  에 막혀 화면 검사가 통째로 빨개진다.

**클립보드** — `navigator.clipboard` 는 **보안 맥락(https)에서만** 있다. 없으면 숨은
textarea + `execCommand` 로 떨어진다. ⚠ 눌렀는데 아무 표시가 없으면 사람은 안 된 줄 안다 —
반드시 단추 글자를 바꿔 알린다("베꼈다 ✓"). 휴대폰에는 `navigator.share` 가 있으면 그쪽을 함께 둔다.

### 칸을 눌러 걸어가기 (탭 이동 · 2026-09-18)

Shattered Pixel Dungeon 이 휴대폰에서 정통 로그라이크를 성립시킨 자리다 — 가상 방향키를
쓰지 않고 **빈 칸을 누르면 거기까지 걸어가고 적을 누르면 때린다.** 방향 패드가 화면 아래
151px 를 먹고 있었는데(사용자: "화면이 좁아 조작이 힘들다) 이걸 넣고 패드를 접으면
**캔버스가 376 → 509px** 이 된다(390×844 실측 · +35%).

```
game.js    pathTo(tx, ty)        목적지까지의 길 (BFS)
           visibleMonsters()     지금 보이는 몬스터 — "새로 나타난 놈" 판정에 쓴다
render.js  tileAtPoint(cx, cy)   화면 좌표 → 칸
           drawGoal()            목적지 표식 (깜박인다)
main.js    tapTile(tx, ty)       누른 칸 해석 · travelTick() 한 걸음씩
```

- **자동으로 걷는 중에는 반드시 멈출 조건이 있어야 한다.** 안 두면 걸어가다 맞아 죽는다.
  멈추는 이유 여섯: ① 못 보던 몬스터가 눈에 들어왔다 ② 체력이 줄었다 ③ 층이 바뀌었다
  ④ 레벨업·상점 창이 열렸다 ⑤ 길이 막혔다 ⑥ 도착했다. 아무 키를 눌러도 멈춘다.
- ⚠ **이미 보이던 몬스터로는 멈추지 않는다.** 그것까지 멈추면 적을 눌러 다가가는 조작이
  첫 걸음에서 취소된다 — 그래서 '시작할 때 보였던 놈' 을 기억해 둔다.
- ⚠ **한 번이라도 본 칸(`lv.seen`)만 지나간다.** 안 막으면 아직 못 본 지형을 뚫고 최적
  경로로 가 버린다 — 탐험이 사라지고, 사람이 모르는 길을 캐릭터만 아는 셈이 된다.
  함정도 **드러난 것(`traps===2`)만** 피한다. 숨은 함정을 피하면 같은 문제다.
- ⚠ **`click` 하나로 끝내면 안 된다.** 터치에서 `click` 은 300ms 뒤에 오고 그 사이 스크롤·
  확대 판정이 끼어 느리게 느껴진다. `touchstart`/`touchend` 로 먼저 처리하고 그때
  `click` 을 600ms 삼킨다(둘 다 받으면 두 번 눌린다). 손가락이 14px 넘게 움직였으면 취소.
- ⚠ **목적지 표식을 반드시 그린다.** 없으면 "왜 혼자 움직이지" 가 된다.
- ⚠ `tileAtPoint` 는 **카메라 흔들림을 빼고** 계산한다(맞는 순간에 누른 칸이 어긋난다).
  그리고 캔버스는 CSS 픽셀 ≠ 실제 픽셀이므로 반드시 `getBoundingClientRect` 를 쓴다 —
  `devicePixelRatio` 를 잘못 쓰면 2배 어긋나고, 증상은 "엉뚱한 데로 걸어간다" 뿐이다.

**패드 접기** — 탭 이동이 생겼으니 패드는 선택이다.

- ⚠ **접힌 상태에서도 펴는 손잡이는 항상 보인다.** 완전히 감추면 저장된 "접힘" 때문에
  조작 수단이 사라진다(옛 `rl_pad` 토글이 그 사고를 냈다). 실측으로 확인한다.
- ⚠ 손잡이를 패드 바깥에 작게 붙였다가 **21px** 가 되어 손가락으로 못 눌렀다(검사에서
  잡혔다). **십자의 비어 있는 왼쪽 위 칸(1/1)** 에 넣으면 자리를 더 안 쓰고 44×42 를 얻는다.
- ⚠ 접고 펼 때마다 `view.resize()` 를 부른다 — 안 부르면 캔버스가 옛 크기로 남는다.

**캔버스에 그린 글자는 DOM 넘침 검사에 안 잡힌다.** 390px 에서 긴 기록이 오른쪽으로
새어 나가고 있었는데 "가로 넘침 0" 이 떠 있었다. 휴대폰에서는 토스트가 **유일한 기록**이라
잘리면 정보가 통째로 사라진다 — `wrapText()` 로 접는다(말줄임 금지, 같은 이유).
⚠ 한국어는 띄어쓰기가 드물어 한 덩어리가 상자보다 길 수 있다 — 그때는 글자 단위로 끊는다.
점검기는 `__toastBoxes()` 로 **그려진 상자**를 받아 넘침을 센다.

**검사에서 배운 것**

- ⚠ **새 검사를 최종 판정(`pass`)에 넣지 않으면 빨간 줄이 떠도 "통과" 가 나온다.**
  실제로 탭 이동 실패가 그렇게 통과로 나왔다.
- ⚠ `game.spawn()` 은 **객체만 돌려준다** — `game.monsters` 에 넣는 것은 부르는 쪽 일이다.
  검사에서 빠뜨렸다가 "적이 나타났는데 안 멈춘다" 는 **거짓 실패**를 봤다.
- 안전 규칙은 실제 판에서 언제 적이 나타날지 정할 수 없어 검사가 성립하지 않는다 —
  `__putMonster()` 로 눈앞에 쥐를 놓아 직접 확인한다(`__force` 와 같은 검사용 창구).

### 구역 보스 넷 · 도전 과제 (2026-09-19)

**구역 보스.** 10층 끝에 군주 하나뿐이라 가는 길에 **사건이 없었다.** 구역 끝
(2·4·6·8층)에 하나씩 둔다. 굳은 문지기 · 물에 잠긴 자 · 멈춘 사서 · 뼈 무덤 주인.
각자 그 구역의 색과 성격을 쓴다(문지기는 느리고 단단하다 · 물에 잠긴 자는 둔화와
물안개 소환 · 멈춘 사서는 원거리와 실명 · 뼈 무덤 주인은 해골 궁수를 부른다).

⚠ 도트는 군주보다 **작게** 그린다. 구역 보스가 군주만큼 커 보이면 마지막이
마지막 같지 않다. 대신 잡몹보다는 확실히 크고 표식(왕관·뿔·빛)이 있다.
⚠ `zoneBoss` 는 **층 배수를 안 받는다**(군주와 같다). 손잡이 하나에 두 가지가
달리면 조정이 불가능해진다. `boss` 와는 다른 플래그다 — 그쪽은 "잡으면 이긴다".
⚠ **잡을 값어치를 준다.** 처음엔 위험만 주고 보상이 없었는데, 그러면 피해 가는
것이 늘 정답이라 사건이 아니라 장애물이 된다. 쓰러뜨리면 두 층 깊은 값으로 굴린
물건을 떨군다(보물방과 **같은 규칙**을 쓴다 — 두 벌로 두지 않는다).

| | 다인 | 셰라 | 오르넬 | 평균 |
|---|---|---|---|---|
| 넣기 전 | 45.4 | 44.6 | 51.7 | 47.2 |
| 보스 넷을 넣고 | 37.1 | 38.8 | 45.8 | **40.6** |
| 25% 깎고 전리품을 주고(최종) | 40.8 | 44.2 | 50.8 | 45.3 |

평균 층수(8.7 → 9.1)와 점수(15.5k → 16.6k)가 함께 올랐다 — 더 위험해졌지만 더
멀리 간다. 사건이 보상을 함께 들고 왔다는 뜻이다.

**도전 과제 열.** ⚠ **힘을 주지 않는다.** Brogue 의 "노 그라인딩" 원칙이다 —
해금이 세지는 길이 되면 처음 여는 사람만 어려운 게임이 되고 죽는 것이 손해가 된다.
전부 기록이고 게임 규칙을 한 톨도 안 바꾼다. "쌓아 두면 강해진다" 가 아니라
"이렇게도 해 봤는가" 를 묻는다(물약 없이 · 저주받은 장비를 낀 채 · 깊은 계단만).
⚠ 시작 화면에는 **몇을 모았는지만** 보인다. 무엇인지는 끝난 뒤에 보인다 —
안 그러면 스포일러다.
⚠ 판이 **끝난 뒤에 한 번만** 센다. 도중에 세면 "물약 없이" 같은 아직 안 끝난
조건이 달성으로 잡힌다.
⚠ 저장이 막힌 환경(시크릿 모드)에서도 게임은 그대로 돈다 — 못 적을 뿐이다.

### 위험도 · 트리거 유물 · 저주받은 장비 (2026-09-19)

**위험도 표시.** Brogue 의 원칙을 따른다: 난이도를 모호함으로 만들지 않는다.
몬스터 머리 위에 **몇 대에 죽는가**를 삼각 1~3개로 보인다.
⚠ 숫자를 안 적는다. 32px 칸 위에 숫자를 얹으면 지도가 표가 된다.
⚠ 색만 쓰지 않는다(색맹). **개수**가 같이 말한다.
⚠ `roll()` 의 **평균**으로 잰다. 최댓값이면 다 위험해 보이고 최솟값이면 아무것도
안 위험해 보인다. 방벽은 셈에 안 넣는다 — 한 번 쓰면 사라지는 것을 상시 방어로
치면 위험이 실제보다 낮게 보인다.
⚠ 안전한 놈에게는 **아무것도 안 그린다.** 다 그리면 아무것도 안 읽힌다.
실측: 굶주린 쥐 24대 · 동굴 트롤 6대.

**트리거 유물 넷.** 아무 데도 안 물리는 유물은 "수치 +N" 과 다를 것이 없다.
넷 다 **오늘 만든 체계**에 물린다.

| 유물 | 어디에 물리나 |
|---|---|
| 물러선 자리 | 기회 공격 — 물러서다 맞으면 그 적이 중독된다 |
| 식은 칼날 | 치명타 — 터지면 모든 쿨다운이 1 줄어든다 |
| 깊은 약속 | 깊은 계단 — 그 층에 물건이 둘 더 |
| 겁쟁이의 종 | 도망·공포 — 등을 돌린 놈이 취약해진다 |

**저주받은 장비.** 조사한 바로는 "귀찮기만 하고 쉽게 벗는 저주" 가 제일 나쁘고,
"아무 위험 없이 다 껴 볼 수 있으면 그 놀이는 뜻이 없다".
⚠ 이 게임은 **자동 착용**이 있다. 몰래 걸리는 저주를 넣으면 주웠더니 갇히는
사고가 된다. 그래서 **보이는 도박**으로 만들었다 — 이름 맨 앞에 "저주받은" 이
붙고, 값이 45% 크고, **한 번 끼면 그 칸을 못 바꾼다.** 자동으로는 안 낀다.
⚠ **나가는 문을 하나 남긴다**(벼림 두루마리가 저주를 끊는다). 끝까지 갇히면 그
판이 통째로 재미없어진다 — 무게는 주되 사형은 아니어야 한다.

**전술 두루마리 둘.** 겁주는(공포) · 먹구름(실명). 공포와 실명은 몬스터만 걸던
것이라 **써 볼 자리가 없었다.** 그리고 이 둘이 이 게임의 **도망 수단**이다 —
기회 공격 때문에 걸어서는 못 빠져나온다.

**실측(240판/직업).** 여기서도 같은 함정을 한 번 더 밟았다.

| | 다인 | 셰라 | 오르넬 | 평균 |
|---|---|---|---|---|
| 넣기 전 | 47.9 | 50.0 | 49.6 | 49.2 |
| 저주까지 넣고 | 37.9 | 37.1 | 48.3 | **41.1** |
| 시뮬 AI 가 저주를 판단하게 하고 | 38.3 | 43.3 | 51.2 | 44.3 |
| 성벽 강화 · 저주 값 1.45 (최종) | 45.4 | 44.6 | 51.7 | 47.2 |

⚠ **AI 가 못 쓰는 선택지는 승률을 통째로 깎는다.** 저주받은 것을 안 끼게 했더니
장비의 10%가 그냥 없어진 전리품이 되어 −8%p 였다. 제품이 아니라 AI 탓이었다.
사람은 값이 크면 낀다 — 시뮬도 그래야 정직하다(25% 넘게 나을 때만 낀다).
**깊은 계단 · 특화에 이어 세 번째로 같은 함정이다.**

⚠ 탭 이동 검사가 **네 번째**로 빨개졌다. 이번엔 "0칸 이동" — 몬스터가 늘면서
외길이 막혔다. `pathTo` 는 몬스터가 선 칸을 안 지나가므로 그게 맞게 군 것이다.
`__pathLen` 을 내놓아 검사가 "길이 있었는가" 를 먼저 보게 했다. 이 검사가
빨개진 이유 넷: 붙은 적 · 원거리 · 새로 나타난 적 · 길 막힘. 전부 제품이 규칙대로
군 것이었다.

### 특화 — 직업 셋이 여섯 갈래가 된다 (2026-09-19)

신규 직업 셋을 만드는 것보다 **3직업 × 2특화 = 여섯 갈래**가 싸다. 조사한 게임들도
**보스 하나를 넘긴 뒤** 갈래를 고르게 한다 — 아무 레벨이 아니라 이정표여야 하고,
"그 판에 맞는" 선택이 되어야 한다.

우리는 **5층에 들어설 때** 한 번 고른다(절반을 내려왔고 빌드 모양이 이미 보인다).

| 직업 | 살아남는 쪽 | 몰아치는 쪽 |
|---|---|---|
| 다인 | 성벽 — 방어 +3 · 최대 체력 +18 | 돌파 — 공격 +4 · 치명 +8% · 체력 −10 |
| 셰라 | 독날 — 상태이상 확률 +26% · 피해 +65% | 그림자 — 치명 +17% · 배수 +0.55 |
| 오르넬 | 시계 — 쿨다운 −1 · 스킬 피해 +12% | 잿불 — 스킬 피해 +30% |

⚠ **레벨업 선택과 같은 통**(`pendingPerks`)을 쓴다. 창을 따로 만들면 배선이 두
벌이 되고 한쪽만 고쳐진다. `busy()` 도 그대로 막아 준다. 레벨업 선택이 이미 떠
있으면 **줄을 세운다**(`pendingQueue`) — 덮어쓰면 레벨업 선택이 통째로 사라진다.
⚠ 값은 특성과 **같은 통**(`player.perks`)에 더한다. 따로 두면 `stats()` 가 두
곳을 합쳐야 하고 반드시 한쪽을 빠뜨린다.
⚠ `hpFlat` 은 최대치만 올린다 — 지금 체력도 같이 올려야 "최대 체력이 늘었는데
안 찼다" 가 안 된다. 음수(돌파)도 같은 길을 타되 1 밑으로 안 내린다.

**실측(240판/직업).** 여기서 배운 것이 둘이다.

| | 다인 | 셰라 | 오르넬 | 직업 격차 | 갈래 격차 |
|---|---|---|---|---|---|
| 넣기 전 | 40.4 | 40.8 | 51.7 | 11.3%p | |
| 처음 값 | 51.7 | 51.7 | 54.2 | 2.5%p | **18.5%p** |
| 전부 깎고 | 51.7 | 40.4 | 55.8 | 15.4%p | 3.3%p |
| 도적↑ 마법사↓ (최종) | 47.9 | 50.0 | 49.6 | **2.1%p** | **7.8%p** |

⚠ **직업 평균만 보면 한 갈래가 죽어 있어도 안 보인다.** 둘을 반반 고르므로
한쪽이 0% 여도 다른 쪽이 두 배면 평균이 그대로다. 처음에 오르넬 평균이 54.2% 로
멀쩡해 보였는데 갈래별로는 잿불 48% · **시계 67%** 였다 — 쿨다운 감소가 스킬
피해보다 훨씬 셌다. `verify` 가 이제 갈래별로 나눠 센다.
⚠ **시뮬 AI 가 새 선택지를 갈아 가며 고르게** 해야 한다. 늘 첫 칸을 고르면 둘째
갈래가 한 번도 안 돌아 밸런스에 안 잡힌다(깊은 계단 때와 같은 함정이다).
⚠ 갈래별 셈은 **본 루프 안에서** 한다. 따로 한 번 더 돌리면 밸런스 검사 시간이
그대로 두 배가 된다.

### 계단이 둘 — 판단이 점수가 된다 (2026-09-19)

10층 외길이라 "어디로 갈까" 가 없었다. 층마다 계단을 **둘** 둔다.

| | 평범한 계단 | 깊은 계단 |
|---|---|---|
| 다음 층 몬스터 | 그대로 | **1.7배** |
| 엘리트 확률 | 그대로 | **두 배** |
| 다음 층 물건 | 그대로 | **1.5배** |

⚠ **고르기 전에 무엇을 고르는지 보여야 한다**(조사에서 얻은 원칙). 밟으면 기록에
"깊은 계단이다. 아래가 더 험하지만 더 많다" 가 뜨고, 도트도 색과 아래 불빛으로
다르다 — 다만 **모양은 같은 계단**이다. 너무 다르게 그리면 "계단" 으로 안 읽혀
선택지가 아니라 못 보던 물건이 된다.
⚠ 두 계단은 시작 방과 서로에게서 **둘 다 먼** 방에 둔다. 몰려 있으면 고르는 것이
아니라 가까운 것을 밟는 것이 된다(`dungeon.js` 의 `Math.min(d1, d2)` 최대화).
⚠ 칸 종류를 `DEEP` 으로 따로 뒀다. `STAIRS` 로 같이 두면 어느 쪽을 밟았는지
구별할 수가 없다. 그리고 판정은 `Game.isStairs` **한 곳**이다 — 쓰는 쪽이 각자
`=== D.STAIRS` 를 적으면 한 곳만 빠뜨려도 거기서만 안 내려간다.
⚠ 어느 계단으로 내려왔는지를 `deepFloor` 로 **spawn 까지** 넘긴다. 지역 변수로
두면 엘리트 확률이 안 걸린다.

**실측(240판/직업). 선택이 진짜인지를 정책 셋으로 쟀다.**

| 정책 | 승률 평균 | 점수 |
|---|---|---|
| 깊은 계단이 없던 때 | 44.6% | 10,662 |
| 체력 70% 넘을 때만 깊은 쪽 | 44.3% | **14,626** |
| 늘 깊은 쪽(욕심) | **40.8%** | 14,909 |

⚠ **처음엔 선택이 아니었다.** 몬스터 1.35배 · 물건 1.6배로 뒀더니 "늘 깊은 쪽"
(47.6%)이 "판단해서" (47.0%)보다 오히려 나았다 — 공짜 보상이었다. 마릿수만
늘리면 경험치와 금화가 같이 늘어 **이득이 된다.** 위험은 수가 아니라 **질**로
줘야 한다(엘리트 두 배). 그러자 욕심이 3.5%p 를 냈다.
⚠ 새 선택지를 넣으면 **시뮬 AI 도 그걸 쓰게** 해야 한다. 안 그러면 그 선택지가
밸런스에 한 번도 안 잡힌다. 그리고 **정책을 바꿔 가며 재야** 선택이 진짜인지
알 수 있다 — 한 정책만 재면 "평균이 괜찮다" 밖에 못 본다.

### 구역 전속 몬스터 — 1층과 9층의 싸움이 같았다 (2026-09-19)

구역은 다섯인데 나오는 놈이 크게 겹쳤다. 구역마다 하나씩, **지금 몬스터 출처가
없던 상태이상**(둔화·실명·공포는 스킬에만 있었다)을 들려 보낸다.

| 구역 | 새 놈 | 성격 |
|---|---|---|
| 물이 든 계단실 3~5 | 물안개 | 느리다(spd 80) · 닿으면 **둔화** |
| 이름의 도서관 5~8 | 먹물 그림자 | **원거리 3** · 눈에 먹을 뿌려 **실명** |
| 뼈 무덤 7~10 | 해골 궁수 | **원거리 5** · 약해지면 달아난다 |
| 군주의 방 9~10 | 지운 자 | 빠르다(spd 130) · **공포** |

겹치던 범위도 좁혔다(쥐 1~3 · 고블린 2~5).

**실측(240판/직업).** 여기서 가장 크게 배운 것:

| | 다인 | 셰라 | 오르넬 | 격차 |
|---|---|---|---|---|
| 넣기 전 | 48.3 | 43.3 | 54.2 | 10.8%p |
| 넷을 넣고 | 35.8 | 47.5 | 46.7 | 11.7%p |
| 원거리 둘을 깎고 | 41.3 | 45.0 | 55.0 | 13.8%p |
| 오르넬 defPerLevel 1 → 0 | 41.3 | 45.0 | **39.6** | 5.4%p |
| defPerLevel 0.5 (최종) | 41.3 | 45.0 | 47.5 | 6.3%p |

⚠ **원거리를 늘리면 근접 직업만 죽는다.** 넷을 넣자 다인이 48.3 → 35.8 로 혼자
떨어졌다(보스 전 사망 51 → 68). 새 둘 중 둘이 원거리였기 때문이다. 원거리 몬스터를
넣을 때는 **직업별로** 봐야 한다 — 평균만 보면 안 보인다.
⚠ **레벨당 방어 0.5 가 승률 8%p 다.** 오르넬을 1 → 0 으로 내리자 55.0 → 39.6
(15.4%p), 0.5 로 올리자 47.5 가 됐다. 이 저장소에서 제일 센 손잡이다.
⚠ 오르넬은 "몸이 약한 대신 스킬이 세다" 인데 `defPerLevel` 이 전사와 **같은 1**
이었다. 설정과 수치가 어긋나 있었다. 도적을 유리대포로 만들 때와 같은 방법을 썼다 —
화력은 그대로 두고 맷집만 깎는다.
⚠ 120판은 표본 오차가 ±4~5%p 다. 격차를 판단할 때는 **240판**으로 다시 잰다.
처음 격차 16.7%p 가 노이즈인 줄 알았는데 240판에서도 13.8%p 로 남아 진짜였다.

### 상태이상 여덟 — 행동을 바꾸는 쪽이 세다 (2026-09-19)

중독·출혈·기절 셋뿐이었다. 다섯을 더해 여덟로 만든다. 조사에서 얻은 원칙은
**"수치를 깎는 것보다 행동을 바꾸는 쪽이 세다"** 였다. 같은 네 턴이라도 "공격력이
조금 준다" 는 안 읽히고 "등을 돌린다" 는 바로 읽힌다. 그래서 새 다섯 중 셋이
행동을 바꾼다.

| | 효과 | 어디서 |
|---|---|---|
| 화상 | 턴당 피해가 가장 크고 가장 짧다(2턴 · 7) | 화염 폭발 |
| 둔화 | 속도 −25. **플레이어가 걸리면 몬스터가 상대적으로 빨라진다** | 지진 |
| 실명 | 시야 −4. 몬스터는 플레이어를 **못 찾아** 다가오지도 던지지도 못한다 | (몬스터용) |
| 공포 | 몬스터가 등을 돌린다. 플레이어는 공격력 ×0.7 | (몬스터용) |
| 취약 | 받는 피해 +18% | 저격 |

⚠ **한 이름이 양쪽에서 다른 뜻이 되지 않게** 적어 뒀다. 둔화는 몬스터를 느리게
하고, 플레이어가 걸리면 같은 한 턴에 몬스터가 더 움직인다 — 한쪽만 구현하면
"내가 느려졌는데 아무 일도 안 난다" 가 된다(`monsterTurn` 의 `pace`).
⚠ 걸린 것들을 더하는 곳은 `ailSum`/`ailHas` **한 곳**이다. 쓰는 쪽이 각자
`who.ail` 을 뒤지면 한 곳만 빠뜨려도 조용히 안 걸린다.
⚠ 취약은 **맞는 쪽에서 한 번만** 곱한다(`damage`). 때리는 쪽에서 곱하면
평타·스킬·상태이상마다 따로 곱해야 하고 반드시 한 곳을 빠뜨린다.
⚠ 실명 시야는 2 밑으로 안 내린다. 0 이면 제 발밑도 안 보여 조작이 불가능해진다.
⚠ 스킬 고유 상태이상은 **무기가 굴리는 중독·출혈보다 먼저** 붙인다. 뒤에 두면
무기 굴림이 터진 판에서만 스킬 효과가 덮여 사라진다.
⚠ 물들이는 색은 **몸이 변하는 넷**(중독·출혈·화상·기절)만이다. 여덟을 다
물들이면 구운 판이 스프라이트당 아홉 벌이 된다.

**실측(120판/직업).** 새 상태이상이 전부 **플레이어 쪽**에 붙어서 처음엔 크게
쉬워졌고, 스킬이 마법사 것이라 **한 직업만 튀었다**:

| | 다인 | 셰라 | 오르넬 | 격차 |
|---|---|---|---|---|
| 넣기 전 | 42.5 | 44.2 | 47.5 | 2.9%p |
| 화상 11 · 둔화 −40 · 취약 30% | 47.5 | 50.0 | **63.3** | 15.8%p |
| 화상 7 · 둔화 −25 · 취약 18%(최종) | 48.3 | 43.3 | 54.2 | 10.8%p |

⚠ **새 효과를 플레이어에게만 주면 한 직업이 튄다.** 스킬 쪽에 붙일 때는 어느
직업의 스킬인지 먼저 세어 볼 것 — 여기서는 셋 다 마법사 계열이었다.

### 몬스터 행동 — 수치보다 행동이 세다 (2026-09-18)

1~10층에 나오는 놈이 전부 **같은 속도의 근접**이었다. 구역은 다섯인데 싸움은
어디서나 같았다. 네 가지 행동을 데이터로 붙인다(`js/data.js` 의 MONSTERS,
`js/game.js` 의 `spawn`·`stepMonster`·`monsterTurn`).

| 값 | 뜻 | 지금 쓰는 곳 |
|---|---|---|
| `spd` | 100 이 사람과 같다. **에너지**로 센다 — 턴마다 spd 를 쌓고 100 마다 한 번 움직인다 | 망령 150 (두 턴에 세 걸음) |
| `ranged` | 이 칸 수 안에서 **보이면 던진다.** 붙으면 그냥 때린다 | 고블린 투석꾼 4 |
| `timid` | 체력이 이 비율 밑이면 등을 돌린다 | 쥐 0.30 · 고블린 0.25 · 투석꾼 0.35 |
| `summon` | `{id, every, max}` | 군주가 해골 병사를 7턴마다 2마리까지 |

⚠ **도망에는 끝이 있어야 한다.** 처음엔 무한정 달아나게 뒀더니 같은 속도라
걸어서는 절대 못 잡아 **시뮬 120판 중 55판이 결판이 안 났다.** 사람도 똑같이
겪는다. 지금은 다섯 걸음 달아나고 돌아서서 죽을 때까지 문다. 구석에 몰리면 그
자리에서 바로 싸운다 — 갈 곳이 없는데 계속 돌아서면 제자리에서 떨기만 하는데,
사람 눈에 제일 먼저 띄는 것이 그 모습이다.

⚠ **원거리 판정은 "플레이어가 그 칸을 보는가" 로 둔다.** 내가 보면 저쪽도 본다 —
안 보이는 데서 날아오면 무엇에 맞았는지 알 수가 없다.

⚠ **한 턴에 세 번까지만 움직인다**(`MAX_ACTS`). 데이터가 잘못 들어와도 화면이
멈추지 않는다. 기절한 놈은 에너지도 안 쌓는다 — 쌓아 두면 풀리는 순간 몰아친다.

⚠ **소환은 그 턴의 행동이다.** 부르고 때리면 한 턴에 두 배가 된다.

**실측(120판/직업). 행동 하나하나의 값을 따로 쟀다.**

| | 승률 평균 | 차이 |
|---|---|---|
| 손대기 전 | 49.7% | |
| 속도 · 도망 · 소환만 | 46.7% | −3.0%p |
| 투석꾼(weight 6 · 사거리 5 · 공격 4)까지 | 37.2% | **−9.5%p** |
| 투석꾼을 깎은 뒤(weight 4 · 사거리 4 · 공격 3 · 3층부터) | 42.5% | −7.2%p (최종) |

⚠ **원거리 하나가 나머지 셋을 합친 것의 세 배를 먹는다.** 붙기까지 공짜로 맞는
횟수가 곧 난이도다. 사거리를 한 칸 줄이는 것이 공격력을 깎는 것보다 크게 먹는다.
원거리 몬스터를 더 넣을 때는 **반드시 이 표를 다시 채울 것.**

⚠ 이 변화로 직업 격차는 오히려 줄었다(4.2%p → 0.0%p). 원거리는 무른 직업만
골라 때리지 않는다 — 셋 다 같은 만큼 맞는다.

### 기회 공격 — 시간이 공짜면 쿨다운도 공짜다 (2026-09-18)

사용자 신고: "몬스터와 마주본 채 위아래로만 움직이면 스킬에 쓴 턴이 그냥 회복된다."
맞았고, 버그가 아니라 규칙 셋이 겹쳐 생긴 구멍이었다.

- 몬스터는 **맨해튼 1** 에서만 때린다(`stepMonster`). 대각선은 거리 2 라 못 때린다.
- 몬스터의 한 턴은 **때리거나 걷거나** 둘 중 하나다.
- 이동이 **4방향**이다.

그래서 붙은 적 앞에서 옆으로 한 칸 비키면 거리가 2 가 되고, 상대는 그 턴을 다시
붙는 데에만 쓴다. 다음 턴에 또 비키면 또 붙기만 한다. **영원히 0 피해**다.

**실측**(`tools/kite-check.mjs` · 100턴 · 대조군은 같은 자리에 가만히 서 있기).

| | 몬스터 공격 | 받은 피해 |
|---|---|---|
| 가만히 서 있기 | 100회 | 814.6 |
| 위아래 춤 (고치기 전) | **0회** | **0** |
| 위아래 춤 (고친 뒤) | 100회 | 814.6 |

춤추며 스킬을 쓰면 100턴에 **20번**을 썼고 받은 피해가 162 였다. 고친 뒤 805 다.

⚠ **진짜 문제는 쿨다운이 아니라 "시간이 공짜" 였다.** 허기도 배회 몬스터도 없고
원거리 몬스터도 아직 없다. 그래서 고치기 전에는 **한 대도 안 맞고 계단까지 걸어
내려갈 수 있었다** — 싸움이 통째로 선택 사항이었다.

**고른 것: 기회 공격.** 붙어 있던 적에게서 **걸어서** 물러나면 한 대 맞는다
(`Game.prototype.opportunity`). 물러나는 것을 막지 않고 **값만 매긴다** —
막으면 불리한 싸움을 접을 방법이 사라진다. 실측 도망 값은 **한 칸당 1.00대**로,
서서 싸우는 것과 같다.

⚠ **실시간 에너지로 바꾸는 쪽은 안 골랐다.** 턴제의 약속("아무리 오래 생각해도
손해가 없다")이 사라지고, 턴 단위로 짜인 것이 전부 무효가 된다 — 「깨진 모래시계」
(쿨다운 −2/턴) · 상태이상 지속 턴 · 무엇보다 `verify.mjs` 의 밸런스 시뮬이
턴제 AI 다. 휴대폰 방향 패드로는 특히 가혹하다. 실시간은 이 구멍의 수리가 아니라
별개의 방향 결정이다.

⚠ **밸런스 검사가 이 변화를 못 본다.** 시뮬 AI 는 붙으면 반드시 때리고 물러나는
일이 없어서, 기회 공격 전후로 360판 결과가 **소수점까지 같았다**(50.0 / 47.5 /
51.7 · 격차 4.2%p). 사람은 물러난다. 그래서 `kite-check.mjs` 를 따로 두고
`verify.mjs` 가 불러 돌린다. 이 규칙을 만질 때 승률만 보고 판단하지 말 것.

⚠ **지금 도망 수단이 없다.** 같은 속도라 걸어서는 절대 못 떼어놓고(실측 12칸을
달아나도 거리는 여전히 1), `돌진` 은 **달려드는** 기술이다. 물러서는 스킬이나
연막 같은 물건을 붙이면 그것이 이 규칙의 출구가 된다.

⚠ **속도가 생긴 뒤 다시 쟀다. 기회 공격은 유지한다.** 장르 표준(NetHack·DCSS)에는
기회 공격이 없고 속도·원거리가 그 일을 한다. 그래서 망령(spd 150)이 생긴 뒤
`kite-check` 로 다시 쟀는데, 기회 공격을 끄면 **오크(속도 100) 상대로는 춤이
다시 0대**로 공짜가 됐다. 망령 상대로만 50대(서 있기의 33%)다. 같은 속도 몬스터가
일곱 중 다섯이라 속도만으로는 못 막는다. 대부분을 빠르거나 원거리로 바꾸면 그때
다시 잰다 — `kite-check` 가 그 표를 들고 있다.

### 타격감 — 넷을 겹친다 (2026-09-18)

사용자 요청: "스킬 쓰면 모션 · 맞으면 피 닳는 효과 · 중독 걸리면 색 · 검이면
내리치고 도적은 쌍검 같은 무기별 모션."

조사한 정석(액션 게임의 "juice")은 **한 방에 넷을 겹치는 것**이다.
① 맞은 그림이 흰색으로 0.1초 번쩍 ② 짧은 히트스톱(보통 50ms · 묵직한 한 방
150ms) ③ **공격 벡터를 따라** 두어 프레임 흔들기 ④ 떠오르는 피해 숫자.
베기 자체는 예비 → 타격 → 마무리 세 마디를 갖춰야 무게가 생긴다.

넣은 것:

| 무엇 | 어디 | 값 |
|---|---|---|
| 무기별 베기 궤적 | `render.js` `SWING` | 검 200ms 넓은 호 · 도끼 280ms 더 크게 · **단검은 두 번 긋는다(쌍검)** · 창은 직선으로 뻗었다 들어옴 · 지팡이는 한 바퀴 고리 · 몬스터 발톱은 세 줄 |
| 스킬 터짐 | `render.js` `BLOOM` | 강타·폭발·지진·독·방벽·치유·돌진·흡수·투척·저격 각각 다른 색과 고리 수 |
| 흰 섬광 | `sprites.js` `bake(name, frame, tint)` | 110ms · 실측 그 칸 밝기 +100% |
| 히트스톱 | `render.js` `freeze` | 보통 55ms · 치명타 120ms |
| 방향 흔들림 | `render.js` `shakeDir` | 공격 축으로 밀고 직각으로만 조금 |
| 피해 숫자 | `render.js` `drawDmgs` | 적이 맞으면 위로 · 내가 맞으면 아래로 |
| 상태이상 색 | `render.js` `tintOf` | 중독 초록 · 출혈 빨강 · 기절 노랑. 실측 초록 비중 0.558 → 0.654 |
| 체력 띠가 닳음 | `render.js` + `style.css` `em.ghost` | 깎인 만큼 어두운 띠가 남았다 뒤따라 줄어든다 |

⚠ **히트스톱은 그림만 멈춘다.** `draw()` 안에서 `dt` 를 0 으로 둘 뿐 규칙도
입력도 안 막는다. 막으면 연타가 밀려 "눌렀는데 안 움직인다" 가 된다. 검사가
**대조군(적 없이 같은 키 두 번)** 과 비교해 턴 수가 같은지 본다.

⚠ **색은 고정된 문자열 넷만 쓴다**(흰색 · 독 · 출혈 · 기절). 알파를 시간에 따라
바꾸면 구운 판이 프레임마다 하나씩 늘어 메모리를 먹는다. `fx-check` 가
한 그림당 8벌을 넘지 않는지 센다(지금 4벌).

⚠ **메인 캔버스에 `source-atop` 을 칠하지 말 것.** 그 합성이 이미 그려진 곳
전체에 걸려 바닥까지 물든다. 스프라이트마다 오프스크린에서 굽는다.

⚠ **상단 체력 띠는 CSS transition 으로 안 된다.** `drawHud` 가 innerHTML 로
통째로 다시 그려서 새 요소는 처음부터 최종 너비다. 그림 고리가 직접 민다.

검사에서 겪은 것(전부 제품이 아니라 **검사의 전제**가 틀린 것이었다):
⚠ 피해 숫자를 칸 하나로 재면 **그 순간 새로 생긴 몬스터 체력 띠**(검은 바탕)가
  같이 들어와 밝은 픽셀이 오히려 줄어든다. 체력 띠 위쪽 띠만 잘라 읽는다.
⚠ 히트스톱 대조군을 **다른 키 둘**로 잡으면 안 된다. 같은 키 연타에만 걸리는
  제한이 있을 수 있어 비교가 성립하지 않는다.
⚠ 연출을 재는 도중에 **플레이어가 맞아 죽으면** 그 뒤 입력이 전부 안 먹혀
  남은 항목이 통째로 거짓 실패한다. `__arena` 가 판마다 체력을 채우고,
  그래도 끝나 있으면 크게 터뜨린다.
⚠ 픽셀만 재면 "안 그려졌다" 와 "애초에 신호가 없었다" 가 안 갈린다 —
  고치는 자리가 전혀 다르다. `__fxState()` 로 쌓인 수를 함께 본다.
⚠ **앞 항목이 남긴 연출이 대조군을 오염시킨다.** 떠 있던 피해 숫자가 "치기 전"
  값에 섞여 들어와 새 숫자를 세도 차이가 안 났다. `settle()` 로 다 가라앉기를
  기다린 뒤에 잰다(그러자 대조군이 0 으로 떨어졌다).
⚠ "밝은 픽셀 수" 로 글자를 재지 말 것. 머리 위 지형 밝기가 회차마다 달라
  대조군이 29~56 으로 널뛰었다. **글자 색 자체**(#f2ead2 · 치명타 #ffb347)를
  세면 지형과 무관해진다. 알파가 1 인 구간(0.43초 안)에 재야 색이 맞는다.
⚠ 맞으면 붉은 막이 화면 전체를 덮어 **밝은 픽셀이 무너진다.** 호가 넓은 무기는
  덮고도 남지만 창처럼 얇은 것은 막에 져서 오히려 어두워졌다(181 → 32).
  궤적을 잴 때는 `__arena({calm:true})` 로 반격을 끈다.
⚠ 한 시점만 찍으면 **궤적이 올라오기 전 프레임**을 잡을 때가 있다. 그러면 무기가
  달라도 "흰 섬광만 있는 같은 그림" 이 되어 자국이 겹친다(다섯 중 넷만 달랐다).
  여러 시점을 찍어 가장 진한 순간으로 판정한다.

### 화면을 픽셀 하나로 (2026-09-19 · UI 제안서 반영)

사용자가 UI/UX 제안서(PDF)를 줬다. 진단 넷과 원칙 셋이 있었고 그대로 갔다.

**진단 1: 폰트가 두 세계로 쪼개짐.** 캐릭터·타일은 도트인데 UI 글자는 산세리프.
⚠ **제안서가 지정한 Press Start 2P + VT323 은 둘 다 한글 글리프가 없다.** 화면이
  전부 한글이라 본문에 그대로 쓰면 한글만 대체 글꼴로 빠져 **오히려 두 세계로
  쪼개진다**(고치려던 바로 그 문제다). 본문은 **갈무리11**(한글 픽셀 비트맵, OFL).

  ⚠ 그렇다고 두 서체를 **안 쓰면 제안서를 안 따른 것이다.** 처음에 `--title` 을
  선언만 하고 아무 데도 안 걸었고 VT323 은 내려받지도 않았다 — 화면은 그대로였다.
  제안서 시안을 다시 보면 한글은 보통 서체인데 **숫자와 라틴**이 도트다("Lv.1",
  "44/44 HP", "28 금"). 답은 고르는 게 아니라 **대체 사슬**이다:

  ```css
  --title: "Press Start 2P", "Galmuri11", var(--sans);   /* 라틴 제목 */
  --num:   "VT323", "GalmuriMono11", "Galmuri11", ui-monospace, monospace;
  ```

  한 덩이 안에 섞여 있어도 브라우저가 **글리프 단위**로 고른다. 숫자·라틴은 앞
  서체가 잡고 한글은 글리프가 없으니 갈무리로 떨어진다. `--num` 은 수치가 실제로
  찍히는 곳에만 건다(`.meter b`·`.stat-line b`·`.hud-num b`·`.shop-cost`·`.score`),
  `--title` 은 8px 짜리 키캡에만(`.skill .k`·`.perk-key`·`.hud-num em`).
  ⚠ VT323 은 같은 px 에서 눈에 띄게 작다. 걸면서 1~3px 씩 키워야 전과 같아 보인다.
⚠ 픽셀 서체는 안티앨리어싱을 끈다(`-webkit-font-smoothing: none`). 켜 두면 11px
  비트맵 가장자리가 흐려져 도트 스프라이트 옆에서 혼자 뭉개 보인다.
⚠ `font-display: swap` + 대체 글꼴을 끝까지 적었다. CDN 이 죽거나 오프라인이어도
  `index.html` 을 더블클릭해 노는 길이 살아 있어야 한다.
⚠ 캔버스는 CSS 변수를 못 읽는다 — `window.TOAST_FONT` 를 `--sans` 와 같은 값으로
  둔다. 두 벌이 되면 화면 안팎의 글자가 달라진다.

**진단 2: 검은 여백이 화면의 절반 이상.** 답은 어둠에 **결**을 주는 것이다.
64x64 알갱이를 한 번 굽고 패턴으로 깐다. 실측 그려진 픽셀 10.7% → 41.7%.
⚠ 프레임마다 난수를 돌리면 어둠이 지글거려 눈이 그쪽으로 끌린다 — 배경은 조용해야
  한다. 밝기도 올리지 말 것. 바닥 타일보다 밝아지면 "여기도 방인가" 로 읽힌다.
· 좌상단 미니맵 · 우하단 층 표시 · 뷰포트 픽셀 테두리로 "떠 있는 느낌" 을 없앴다.
⚠ 미니맵은 **본 칸만** 그리고 **몬스터는 안 그린다.** 안 본 지형을 보여 주면 탐험이,
  적 위치를 보여 주면 시야가 의미를 잃는다.
⚠ 한 층이 62x38 = 2,356칸이다. 매 프레임 칠하면 초당 14만 번이 된다 — **턴이
  바뀔 때만** 다시 굽는다.
⚠ 좁은 화면에서는 한 칸 1px, 층 표시는 **우상단**이다(우하단은 토스트가 가린다).

**진단 3: 우측 패널이 스프레드시트 같음.** 8x8 픽셀 아이콘을 수치 앞에 붙이고
장비·가방을 슬롯으로 바꿨다. 아이콘은 네모 몇 개로 그린 data URI 라 요청이 0건이다.
⚠ 빈 칸도 그린다 — 비어 있다는 것이 정보다. 다만 빈 칸마다 한 줄씩 그렸더니
  **빈 칸 다섯이 세로 130px** 를 먹어 정작 가진 물건이 스크롤 밖으로 밀렸다.
  한 줄짜리 네모 띠가 같은 말을 한다(네모는 열둘까지, 나머지는 숫자로).

**진단 4: 배경-패널 대비가 약함.** 팔레트를 제안서 값으로 올렸다. 특히
`--line` 을 `#352c22 → #4a3826`. 구역 구분이 테두리 하나에 기대고 있었는데 그
선이 안 보였다.
⚠ `--bg` 와 캔버스 바닥색을 **함께** 옮긴다. 한쪽만 밝히면 던전이 화면에 뚫린
  구멍처럼 보인다.

**픽셀 프레임**(원칙 1)은 9-슬라이스 `border-image` 컴포넌트 하나(`--frame`)다.
⚠ 9x9 그림을 3px 로 자른다. 테두리 폭도 3px 여야 픽셀이 딱 떨어진다.
⚠ 막대(`.meter`)에는 안 쓴다. HUD 막대가 15px 인데 3px 테두리 둘이면 속이 9px 만
  남아 색이 안 읽힌다.
⚠ 패널마다 두르면 세로로 패널당 6px 이 는다 — 사이드바 여백을 그만큼 줄였다.
⚠ 큰 창의 **찢긴 양피지 테두리는 그대로 뒀다.** 세계관을 들고 있는 자리다.

**그 밖에**
· 씨앗이 **두 번 흐려져** 있었다(11px 에 opacity .7 을 또 곱함). 흐림을 걷고 뱃지로.
· 기록에 고정 배경 패널 + 갈래 표(전투·피해·처치…) + 최신 줄만 밝고 크게.
· 등급색을 인라인 style 에서 CSS 클래스로(`.rar-*`). 인라인으로는 글자색밖에 못
  바꾼다 — 테두리까지 등급색으로 두려면 클래스여야 한다.
· 문에 **돌 문틀**(기둥 + 인방). 문짝만 있어 벽에 널판을 댄 것처럼 보였다.
· **벽 횃불** 신규. 위 칸이 벽인 자리에만, 서로 네 칸 띄우고, 층당 5개 고정.
  다른 장식과 같이 굴렸더니 벽 조건에 걸러져 층당 1.4개였다(400층 실측).

**장비 착용 → 외형**(제안서 5단계). 캐릭터 도트는 직업마다 한 장이고 **무기까지
그려져 있어** 무기를 덧그리면 두 자루가 된다. 그래서 무기가 아니라 **갑옷 등급**을
어깨 장식으로 얹었다(`eq_magic`·`eq_rare`·`eq_relic`).
⚠ 몸을 가리지 말 것. 어깨선(y 16~21) 바깥쪽만 쓴다 — 가운데를 덮으면 직업이 안
  읽힌다. 세 직업이 **같은 덧그림 한 장**을 쓴다(따로 그리면 아홉 장이 되고 몸을
  고칠 때마다 아홉 곳이 어긋난다).
⚠ 일반 등급에는 안 붙인다. 늘 붙어 있으면 "등급이 올랐다" 가 안 읽힌다.
⚠ 지도와 초상이 **같은 함수**(`armorArt`)로 고른다. 각자 고르면 조용히 어긋난다.
`fx-check` 가 일반 갑옷과 유물 갑옷의 픽셀이 실제로 다른지 잰다.

### 제단 — 가진 것을 내주어야 가진 것이 바뀐다 (2026-09-19)

상점은 **금화**로 물건을 산다. 레벨업 특성은 **더하기만** 한다. 둘 다 "내가 가진
것을 잃는" 결정이 아니다. 조사한 로그라이크들이 그 자리를 제단으로 채우고 있었다.

- **Brogue 의 보상 방에는 값이 있다.** 열쇠를 든 놈을 잡아야 열리거나, 위험한
  현관을 지나야 하거나, 바리케이드를 부숴야 한다. 공짜 보물은 선택이 아니다.
- **Brogue 의 치환 제단은 수치를 주지 않는다.** 물건 둘의 마법 수치를 **맞바꾼다.**
  한 번뿐이고 되돌릴 수 없다. 게다가 방 전체가 치환기라, 바닥에 아무 물건이나
  떨어뜨려 두면 그게 대신 먹힌다 — 보상에 함정이 붙어 있다.
- DCSS 의 제단은 신을 고르는 자리고, 고르는 순간 다른 길이 닫힌다.

그래서 제단에서 파는 것은 전부 **맞교환**이다. 2~9층에 45% 확률로 하나(실측 전체
층의 33.6%), 계단에서 여섯 칸 밖, **한 제단에 거래 하나뿐**.

| 거래 | 내주는 것 | 받는 것 |
|---|---|---|
| 치환 | 제일 높은 등급 | 제일 낮은 등급과 맞바꾼다 |
| 담금질 | 금화 60 + 층×28 | 가장 낮은 등급 한 점을 한 단계 위로 |
| 속죄 | 금화(층에 비례한 바닥값 또는 절반 중 큰 쪽) | 저주를 푼다 |
| 맹세 | 최대 체력 12% | 치명타 +18% · **영구** |

⚠ **거래 목록은 지금 판 상태에서 만든다.** 못 하는 거래를 회색으로 띄우면 네 줄 중
  셋이 회색인 창이 되어 무엇을 할 수 있는지가 안 읽힌다. 장비가 하나뿐이면 치환은
  아예 안 뜬다.
⚠ **대가를 숫자로 적는다.** "체력을 조금" 은 거래가 아니다.
⚠ 치환은 **어느 둘을 바꿀지 고르게 하지 않는다.** 두 단계 창이 되고, 실제로
  재미있는 경우는 "제일 좋은 등급이 쓸모없는 자리에 붙어 있다" 하나뿐이다.
⚠ 속죄는 저주가 **준 힘은 안 걷는다**(`curseMul`). 걷으면 "저주를 푼다" 가 아니라
  "장비를 약하게 만든다" 가 된다. 푸는 것은 묶임뿐이다.
⚠ 제단도 상인처럼 **길을 막지 않는다.** 막으면 계단 가는 길이 제단을 지날 때마다
  창이 열리고 닫힌다(상인에서 이미 겪었다). 다 쓴 제단은 아예 안 열린다.
⚠ 제단 창은 **Enter 로 안 닫는다.** 줄을 숫자로 고르는 창이라 Enter 를 닫기로
  두면 "고르려다 닫는" 사고가 난다. Esc 만 닫는다(상점은 반대로 Enter 도 닫는다 —
  거기는 고를 숫자가 없다).

#### 재서 고친 것 넷

**1. 담금질이 아무 일도 안 했다.** 등급 배수를 곱하고 반올림했더니 방어력 3 을
일반 → 고급으로 올려도 `round(3/1.00*1.12) = 3` 이었다. "불을 먹었다" 고 해 놓고
숫자가 그대로다. 등급이 오르면 **반드시 오르게** 방향을 한 칸 보장했다.

**2. 속죄가 공짜가 될 수 있었다.** 값을 "가진 금화의 절반" 으로만 뒀는데, 상인에게
다 쓰고 오면 0 이 된다. 저주의 무게가 통째로 사라진다. 층에 비례하는 **바닥값**을
깔았다.

**3. AI 가 제단을 무한히 왕복했다.** 360판 중 **57판이 안 끝났다.** 지나치기로
해도 `used` 는 그대로라 다음 턴에 또 목표로 삼는다. 상인에서 겪은 것과 같은
왕복이다. "안 쓰기로 했다" 도 층별로 기억하게 했다.

**4. 맹세가 지배당하는 선택지였다.** 처음 값(최대 체력 −20% / 치명 +15%)으로
대조군 넷을 180판씩 돌렸다.

| 정책 | 평균 승률 | 평균 점수 |
|---|---|---|
| 제단을 안 쓴다 | 46.6% | 16,704 |
| 맹세만 탐한다 | 30.7% | 13,859 |
| 판단해서 넷 다 쓴다 | 49.2% | 16,625 |
| **맹세만 빼고 셋** | **50.6%** | **17,274** |

조심해서 받아도 맹세가 −1.4%p 였고 점수도 낮았다. **늘 거절하는 것이 정답인
선택지는 선택지가 아니다.** 원인은 단순하다: +15% 치명은 치명배수 1.8 에서
대략 공격 +12% 인데 최대 체력 −20% 는 생존 −20% 라 언제나 손해다.

값을 **−12% / +18%** 로 고치고 다시 쟀다.

| 정책 | 평균 승률 |
|---|---|
| 제단을 안 쓴다 | 46.6% |
| 맹세만 탐한다 | 46.7% |
| 맹세만 빼고 셋 | 50.4% |
| **판단해서 넷 다** | **51.5%** |

판단하면 +4.9%p, 탐하면 아무것도 못 얻는다. 깊은 계단 때와 같은 모양이다 —
**값이 진짜라야 판단이 점수가 된다.**
⚠ 맹세를 거듭 쌓으면 셰라의 치명이 100% 에 닿는다. 거기서부터는 더 맺을수록
  순손해라 스스로 멈춘다 — 상한을 따로 두지 않았다.
⚠ 대조군 손잡이(`MB_ALTAR`·`MB_OATH_HP`·`MB_OATH_CRIT`)는 **`tools/verify.mjs`
  에만** 있다. 제품 코드에 두면 배포된 값이 무엇인지 흐려진다.

**5. 그 검사가 곧바로 빨개졌다 — 틀린 것은 검사였다.** 맹세 값을 0.88/0.18 로
고치자 `altar-check` 가 "맹세가 체력을 깎는다 62 → 55" 를 실패로 찍었다. 검사가
0.8 과 0.15 를 **박아 두고** 있었다. 제품이 아니라 검사의 전제가 낡은 것이다
(이 저장소에서 열 번 넘게 그랬다). 검사도 `DATA.ALTAR` 을 보게 고쳤다.

검사는 `tools/altar-check.mjs` 33항목. 규칙은 화면 없이 재고 창만 크롬으로 연다
(전부 크롬으로 재면 규칙이 틀렸는지 배선이 틀렸는지 안 갈린다).

### 오늘의 변이 — 같은 층을 매일 다르게 (2026-09-19)

하루의 장부는 씨앗만 같았다. 씨앗이 같으면 지도가 같고, 지도가 같으면 이틀째부터
**어제 한 대로** 하면 된다. Slay the Spire 의 일일 등반, Dead Cells 의 일일 도전,
Brogue 의 변이 모두 같은 자리에서 같은 답을 냈다: **규칙을 하루씩 비튼다.**

열 가지를 넣었다. 나쁜 것 다섯 · 좋은 것 다섯(`public/js/daily.js`).

| 나쁜 것 | 무엇 | | 좋은 것 | 무엇 |
|---|---|---|---|---|
| 어스름 | 시야 -4 | | 노다지 | 아이템 1.6배 |
| 폐점 | 상점 없음 | | 날램 | 쿨다운 -2 |
| 창궐 | 엘리트 3배 | | 금맥 | 금 더 나옴 |
| 깊은 길만 | 깊은 계단만 | | 이른 눈뜸 | 특화 3층에 |
| 허약 | 최대체력 0.75배 | | 예리 | 치명 +12% |

**하루에 나쁜 것 하나 + 좋은 것 하나.** 무작위로 둘을 뽑으면 "좋은 것 둘 뜬 날" 이
생기고 그날 점수만 장부 위쪽을 차지한다. 한 짝씩 고정하면 **날마다 거래가 다르지
난이도는 안 흔들린다.**

⚠ **어제와 같은 것이 뜨면 안 된다.** 처음엔 "뽑고 나서 어제와 같으면 하나 밀기" 로
  했는데 365일 중 25일이 그대로였다. 어제 것도 이미 밀린 값이라 밀기가 되돌린다.
  답은 뽑지 말고 **걷는 것**이다. 걸음 폭을 `1 ~ len-1` 에서 고르면 0이 될 수 없으니
  연속 반복이 **수학적으로 불가능**하다. 365일 재서 0건.

```js
var step = 1 + (seedOf(salt + "|" + i) % (len - 1));
arr[i] = (arr[i - 1] + step) % len;
```

⚠ **고르기 전에 보여 준다.** 시작 화면에 오늘의 변이 둘을 색으로 갈라 띄운다
  (나쁜 것은 붉게, 좋은 것은 금빛). 들어가 봐야 아는 변이는 변이가 아니라 함정이고,
  직업 고르기가 변이를 보고 하는 판단이 되어야 뜻이 생긴다.
⚠ 장부에 **변이 이름을 적는다.** 공유판을 받은 사람이 "왜 다들 8층에서 죽었나" 를
  알아야 비교가 된다. 자유 탐사 줄에는 안 붙인다.
⚠ 변이 점수는 `rl_best` 에 안 넣는다. 예리 뜬 날 기록이 최고 기록으로 굳는다.
⚠ **`mods` 는 `reset()` 전에 넣는다.** 층을 만들면서 이미 읽는 값이 있다.
⚠ 열 개 키가 실제로 읽히는지 `game.js` 에서 하나씩 확인했다. 선언만 하고 안 읽는
  변이는 화면에만 뜨고 아무 일도 안 일어난다 — 가장 조용한 종류의 거짓말이다.

검사(`tools/daily-check.mjs`)가 365일을 돌려 연속 반복 0 · 조합 25/25 · 같은 날
같은 결과를 잰다.
⚠ 이때 **장부 검사가 빨개졌는데 제품은 맞았다.** 변이 줄이 붙어 장부가 5줄에서
  6줄이 됐는데 검사가 `lines.length === 5` 와 `lines[2]` 로 막대를 찾고 있었다.
  줄 번호로 찾는 것을 전부 **내용으로 찾기**(이모지가 든 줄)로 바꿨다.

### 미술 방향 — 「관리소 장부」 (Darkest Dungeon 결)

세계관이 장부다: 내려간 사람은 이름이 지워지고 **몇 층까지 갔는가**만 남는다. 그래서
화면은 **그을린 양피지에 금물 잉크로 적은 장부**다. `style.css` 끝의 "미술 방향" 절.

- **팔레트는 색상만 돌렸다.** 자보라(#16141c) → 그을린 갈색(#191510). 명도를 그대로
  둔 이유가 둘이다 — 대비 검사가 깨지고, 캔버스의 회색 돌과 톤이 어긋난다.
  ⚠ 채도를 더 올리지 말 것. 갈색이 진해지면 UI 가 던전보다 화려해진다.
- **종이결·찢긴 테두리는 인라인 SVG 다**(`--grain`·`--torn`). 이미지 파일을 쓰면 첫
  화면에서 요청이 늘고 도트와 톤이 어긋난다. ⚠ 캔버스(`#view`)에는 절대 깔지 않는다 —
  도트가 흐려진다.
- ⚠ **카드를 `clip-path` 로 찢으면 안 된다.** 안쪽 스크롤이 함께 잘려 상점 목록이
  사라진다. `border-image` 로 **선만** 거칠게 만들고 상자 모양은 그대로 둔다.
- ⚠ **어두운 배경에 어두운 테두리는 아무도 못 알아본다.** 처음엔 3px·#3f3426 이라
  찢긴 결이 화면에서 보이지 않았다 — 놋쇠 톱니(5px) + 안쪽 마른 잉크선 두 겹으로 갈았다.
  그리고 타일이 72px 이면 `round` 반복이 **기계처럼 규칙적**이어서 손으로 찢은 결로
  안 읽혔다 → 160px 타일에 톱니 높이를 불규칙하게 뒀다.
- **제목 밑줄은 `border-bottom` 이 아니다.** 자 댄 선이 된다. 가운데가 진하고 끝이 마르는
  그라디언트를 `skewX(-14deg)` 로 눕혀야 붓 자국으로 읽힌다.
- ⚠ **막대 눈금을 촘촘히 넣지 말 것.** 9px 간격으로 넣었더니 빨간 체력 막대가 줄무늬로
  읽혀 **남은 체력이 눈에 안 들어왔다**(정보가 장식에 먹힌 것이다). 19px·투명도 .17.
- ⚠ 이 절은 **배치를 바꾸지 않는다.** 폭·높이·padding·flex 는 실측으로 맞춘 값이다
  (390px 헤더 한 줄 · 버튼 42px · 사이드바 27vh). 배경·테두리색·그림자·자간만 쓴다.
- 확인한 것: 전 화면 콘솔오류 0 · 넘침 0 · 오버레이 카드 네 크기에서 **닫기 버튼에
  손이 닿는다**(카드가 `overflow-y: auto` 라 스크롤된다 — 이게 없으면 영영 못 닫는다).

## 배포

지금은 **웹으로 완성하는 단계**다. exe 는 나중에 포장만 하면 되고 코드는 그대로다.

| 방법 | 용량 | 비용 |
|---|---|---|
| itch.io 업로드 | — | 무료 (브라우저 플레이 + 다운로드 동시 제공) |
| Tauri 로 exe 포장 | 약 5~10MB | 무료 (윈도우 내장 WebView 사용) |
| Electron 으로 포장 | 약 150MB | 무료 (크롬을 통째로 넣는다 — 이 게임엔 과함) |
| Steam 출시 | — | 게임당 $100 (매출 발생 시 환급) |

권장 순서: **웹 완성 → itch.io 무료 공개 → 반응 보고 Tauri exe + Steam**.
처음부터 exe 로 개발하면 매번 빌드해야 해서 속도가 절반이 된다.

⚠ 한국에서 **유료 판매**할 때는 게임물 등급분류가 걸린다. 해외 플랫폼 경유 시 실제
적용 방식은 판매 단계에서 게임물관리위원회에 직접 확인할 것. 무료 공개는 해당 없다.
